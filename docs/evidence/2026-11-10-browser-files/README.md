# Browser / Files: курсор и фоновая работа — 10 ноября 2026

## Объём

Подготовка исходников по просьбе владельца: ремонт Browser/Files и управление
браузером с джоя как мышью. Установки на Flip/Odin и замена полного Setup остаются
приостановленными. Процессные изменения предыдущего
[прохода Apps](../2026-11-10-apps-lifecycle/README.md) сохранены.

- Левый стик двигает курсор, правый прокручивает страницу. Confirm кликает,
  R3 открывает контекстное меню, Back закрывает меню / возвращает назад,
  Select открывает управление. Локальные меню сохраняют управление крестовиной;
  на веб-странице крестовина сдвигает курсор. Подсказки учитывают семейство джоя.
  L1/R1 и L2/R2 продолжают управлять уровнями оболочки. Системные X/Y/Home/Start
  не переназначены. Удержание Confirm по-прежнему вызывает действия.
- В BrowserPane убран полный поиск DOM-элементов с измерением координат на каждый
  шаг навигации. Клик на локальном стартовом экране попадает под курсор,
  вместо активации ранее выделенной плитки. Используются настоящие Qt mouse /
  wheel events, без DOM-скриптов для обычного управления.
- Опрос редактируемого поля: 750 ms в простое, 120 ms при вводе и две секунды
  после запроса проверки фокуса; явная проверка после клика — через 140 ms.
  Опрос прекращается без переднего плана, страницы или под локальным диалогом.
- BrowserEngine явно скрывает страницу за внешним приложением. Невидимая вкладка
  замораживается через 15 s только при разрешающем Chromium recommendedState.
  Посторонняя paused/running-загрузка больше не блокирует заморозку всех вкладок.
  Профиль сохраняет загрузки; Discarded, автоматической перезагрузки и потери DOM
  не добавлено. Ленивое создание страниц сохранено.
- FilesService отменяет прежний libfm DirListJob и объединяет переходы в одном
  обороте event loop. Старое поколение результата остаётся недействительным.
  Отмена чтения отделена от пользовательских copy/move/delete и иных операций.
  Сортировка и sizeLabel готовятся в рабочем потоке. FilesController возвращает
  подготовленные строки и обновляет выделение при его изменении; rows() больше
  не пересобирает каждую карту и не форматирует все размеры заново.

## Среда и воспроизведение

Изолированная серверная Fedora 44 / Qt 6.11 Release-сборка с настоящим Qt WebEngine
и libfm: образ `traineros-browser-ci:20261110`, на основе прежнего
`traineros-home-pet-ci:full` с qt6-qtwebengine-devel. Сборка `traineros`,
`trainer_browser_tests`, `trainer_files_tests`, `trainer_interaction_tests`,
`trainer_browser_probe` прошла.

Runtime: обычный UID 1000, отдельные HOME / профиль / Downloads, Docker
`--network none`, стандартная sandbox Chromium включена, Xvfb и software rendering.
Внешние сайты, личные сессии и файлы не использованы. SDL virtual gamepad проходит
через настоящий ControllerInput. Геометрия тестовых DOM-элементов используется
только для прицеливания теста; производственная навигация DOM не обходит.

`tests/browser_fixture.py` обслуживает только loopback. `trainer_browser_probe`
запускается с PROBE_MODE `mouse`, `lifecycle`, `input`, PROBE_SCENARIO на
соответствующий `tests/ui/Browser*Probe.qml`, PROBE_KEYBOARD на реальный
KeyboardPanel.qml, PROBE_URL на локальную fixture (`/input` для текстового теста),
PROBE_DATA на отдельный пустой каталог. Компоненты загружаются с настоящим Theme,
ресурсы шрифтов/иконок включены в тестовую программу.

## Проверки

Пять наборов прошли: `browser`, `trainer_files_tests`, `interactions`,
`apps_qml_smoke`, `crates_qml_smoke`. Новые проверки покрывают отмену чтения при
ожидающем конфликте копирования, сохранение обоих файлов после Keep both,
сортировку/выделение/поиск, R3 → Browser и сохранение переходов между подвкладками.

Первый прогон UI не смог сохранить снимки в каталоги прежнего root-builder.
Исправлены права только тестовых каталогов; оба набора прошли повторно.
Первый mouse-прогон дошёл до поля, но Xvfb-окно не имело активного состояния Qt.
Добавлена явная активация тестового окна до сценария, проверки не ослаблены.
Lifecycle-проба переведена с фиктивной темы на ту же регистрацию настоящих QML
компонентов; устранены предупреждения об undefined scale/color.

Настоящие Chromium-пробы прошли:

- Mouse, stage 11: SDL-стик → курсор, hover, Confirm → клик, R3 → контекст ссылки,
  Back → закрытие, правый стик → scroll, клик поля → общая клавиатура → текст в DOM,
  клик указателем по адресу локальной стартовой страницы.
- Lifecycle, exit 0: ленивое создание, paused download, Frozen у другой скрытой
  страницы, восстановление её DOM после Active, сохранение исходной страницы,
  продолжение загрузки в фоне и освобождение закрытой вкладки.
- Input, stage 62: реальная клавиатура, выделение, Unicode, input events,
  contenteditable, shadow DOM, cross-origin iframe, пароль, Tab, multiline,
  hide/readonly/stale input, Ctrl A/C/X/V/Z/Y, раскладка, цифры и повторные буквы.
- Скачано 12 582 912 байт; SHA-256 совпадает с детерминированным HTTP-эталоном:
  `8b54debaa89f78212f6afb00c7ebb2780f3604c4caa8c97c395576a50d5d6a6a`.

Снимок локального старта после mouse-сценария просмотрен; это компонентная
проверка, а не снимок полноценной оболочки на устройстве.

Артефакты: локально `build/browser-files-20261110/`, на сервере

## Недоделано / границы

Не проверены физические стики/касания, скорость и потребление памяти на Flip,
Gamescope/аппаратное ускорение и реальные медленные microSD/сетевые папки.
Нет численного обещания ускорения устройства. Заморозка сокращает фоновую работу,
но не освобождает renderer как Discarded; память множества посещённых вкладок
остаётся отдельным предметом измерения. Выгрузка с потерей форм не вводилась.
Крупный фильтр Files ещё выполняется в UI; новые изменения не заявляют виртуальную
модель для неограниченного числа файлов. Read-only fallback использует QDir и
не умеет прервать сам entryInfoList; production backend — libfm.
Подготовленный полный Setup из `dc378c7b` не заменён и этих изменений не содержит.
