# Ship Home — управление кораблём и стыковкой: аудит и проект новой схемы

> **Статус: АУДИТ + ПРЕДЛОЖЕНИЕ, НЕ УТВЕРЖДЁННОЕ НАЗНАЧЕНИЕ КНОПОК.** 22 ноября 2026. Владелец сообщил, что существенная часть действий отсутствует на геймпаде, а имеющиеся кнопки назначены неудобно. Этот документ фиксирует прочитанный код и **кандидат** для обсуждения. **Код управления, режимы полёта, тесты и установленные сборки пока не менялись**.
>
> Основной ориентир: **Elite Dangerous + Warframe + Animal Crossing**; физическая пилотажная модель с контроллером, не «пианино» из случайных хорд. См. [полную карту Ship Home и Эгрегора](SHIP_HOME_EGREGORE_DISCUSSION_RU.md), [обзор текущей сцены](../experiences/ship-home/README.md).

## 1. Что фактически назначено сейчас

**Реальные источники:** `experiences/ship-home/scripts/home.gd::_inputs/_unhandled_input/_fly_manual`, `helm_display.gd::event/rows/activate`, `egregore_flight.gd::clearance/interact/tick`, `ship_avionics.gd::hail/plot/jump/boost_drive/...`, `sector_chart.gd`, `project.godot`, `ship_prompts.gd`. В Godot используется **позиционный** ввод, а подписи на экранных подсказках сейчас жёстко адаптированы под Nintendo-раскладку (Joy B = A справа, Joy A = B снизу, Joy Y = X сверху, Joy X = Y слева). Для разных контроллеров нельзя слепо копировать подпись A/B без учёта семейства.

| Сейчас | Фактическое действие | Проблема |
| --- | --- | --- |
| LS | Тангаж/рысканье | В принципе пригодно |
| RS | Взгляд по кокпиту | Для 6DOF манёвров особенно возле платформы неудобно использовать D-pad вместо отдельного стика |
| LT / RT | Тормоз/двухэтапный реверс / тяга вперёд | Полезная основа; сложный LT необходимо показать в подсказках |
| LB / RB | Крен; в каталогах листание | Роль меняется по открытому интерфейсу, это допустимый явный контекст |
| D-pad | Горизонтальная/вертикальная тяга; при Y + D-pad выбор 4 приборных панелей | Перегрузка и отсутствие быстрого доступа к приборным панелям |
| A справа (Godot `JOY_BUTTON_B`) | Взлёт / посадка / стрельба при выпущенных орудиях | Одна кнопка совершает несвязанные критические действия |
| B снизу (Godot `JOY_BUTTON_A`) | Выйти из кресла, включая полёт/автопосадку | Возможны случайные выходы; но **возможность ходить по кораблю во время полёта надо сохранить** |
| X сверху (Godot `JOY_BUTTON_Y`, action `decorate`) | Торможение во время полёта | Дублирует LT, название action не по смыслу |
| Y слева (Godot `JOY_BUTTON_X`) | Коротко — цель по курсу; удерживать + D-pad — панели; с L3 — режим прицела; с A — противоракетная защита | Сложно обнаружить; панели требуют комбинаций |
| L3 | Смена оружия | Ускорение (boost) прямой кнопки не имеет |
| R3 | Приближение к радару / Scope | Быстрой стабилизации/precision mode нет |
| Start | Меню паузы | Оставить |
| View/Select | Не используется как штатная прямая команда пилотирования | Резерв для оружия/режимов |
| Панели/карта | Устройства, нацеливание, lock, hail, request pad, cruise, boost, shift jump, engine service, power и т.д. | Формально доступны через меню, но крайне неудобны для частых действий в полёте |

**Дополнительный UX-дефект:** `_action_hints()` показывает `A · Land` только при уже выполненных условиях. Если разрешение отсутствует, прямой подсказки `A · Request clearance` нет — игрок должен догадаться открыть Contacts → выбрать станцию → Contact → Request pad 01.

**Ещё один технический риск:** когда открывается панель, `home.gd::_physics_process` передаёт нулевые управляющие оси в `flight.tick(... brake=false)`, но сохранившийся `throttle` и инерция корабля не обязательно обнуляются. Игрок читает меню разрешения на стоянку, а корабль может продолжать движение. Нужно независимое от интерфейса поведение полётного ассистента.

## 2. Предлагаемый default: два стика и понятные режимы [КАНДИДАТ]

**Решение не утверждено.** Подписи ниже ориентированы на расположение кнопок на Odin 2 / Retroid (A справа, B снизу, X сверху, Y слева). Реальный SDL/Godot button index и отображаемые названия должны определяться input profile, не зашиваться на все устройства.

| Ввод | Полёт без открытой панели |
| --- | --- |
| **Левый стик** | Тангаж + рысканье, как сейчас |
| **Правый стик** | Движение влево/вправо и вверх/вниз (strafe/lift), **не поворот камеры**; важен для мягкой стыковки |
| **RT / LT** | Тяга вперёд / торможение и повторное нажатие для реверса |
| **LB / RB** | Крен влево/вправо |
| **L3** | Мгновенный boost, если хватает энергии/условия выполнены |
| **R3** | Восстановить вид вперёд; длительное нажатие — Scope. Точную семантику ещё согласовать |
| **D-pad ←/→/↑/↓** | Напрямую: Contacts / Ship systems / Egregore atlas / Power (панели без Y-модификатора) |
| **Y (слева), коротко** | Выбрать контакт перед носом; дополнительный target lock — контекст для боевого режима |
| **Удерживать Y + правый стик** | Осмотреть cockpit (freelook), не давать боковую/вертикальную тягу |
| **A (справа)** | Единая **контекстная кнопка**, никогда не стреляет: старт/взлёт, запрос разрешения у выбранной станции, финальная посадка, согласованное действие с целевым контактом |
| **B (снизу), коротко в полёте** | Стабилизация/precision assist: сброс скорости, автогоризонт, ограниченные манёвровые тяги. При выполняющейся посадке — отменить до точки невозврата |
| **Удерживать B** | Встать с кресла и передать корабль в устойчивый автоподхват/hover; безопасная прогулка по жилому отсеку во время полёта сохраняется |
| **X (сверху), когда оружие убрано** | Включить/выключить Cruise |
| **X, когда оружие выпущено** | Стрельба; обозначить режим явно на HUD, не смешивать с посадкой |
| **View/Select** | Выпустить/убрать орудия (armed/unarmed — явный режим) |
| **Start** | Пауза/системное меню |

**Боевые быстрые действия — кандидат:** Y + LB/RB — переключить группу вооружения, Y + A — противоракетная защита, A с оружием на цели — target lock вместо посадки (при выпущенных орудиях станционная посадка запрещена). Окончательно развести взаимодействие/lock, исключить двойные команды от одной кнопки. Излишнее количество хорд не допускать: основное оружие, навигация, boost, круиз, стыковка должны работать без комбинаций.

**Панели:** открытие D-pad не должно создавать управляющую тягу; внутри панели D-pad перемещает фокус, A подтверждает, B возвращает, вызов той же панели/выход её закрывает. Для 3D-карты RS вращает, LT/RT масштабируют, LB/RB переключают кластеры. Отдельные экраны не должны одновременно двигать корабль бесконтрольно.

**Предельная альтернатива [ОТКРЫТО]:** оставить RS свободным взглядом в основном полёте, а RS-маневрирование включать только при proximity docking. Но это создаёт меняющуюся реакцию стика на одной и той же фазе полёта. Основной кандидат выше предпочтительнее **как предложение**, без одобрения владельца не фиксировать окончательно.

## 3. Проблемы текущей стыковки

`egregore_flight.gd::clearance()`:

| Условие | Остров | Станция |
| --- | --- | --- |
| Радиус по горизонтали | До **80 м** | **8 м** |
| Относительная высота | От −2 до +120 м | Приблизительно от −0,3 до +9 м |
| Скорость | В существующем пути island assist прямого лимита нет | Менее **2,5 м/с** |
| Ориентация | При посадке автовыравнивание | Почти горизонтальная (dot up > 0,94) |
| Запрос разрешения | Не нужен | Обязателен: Contacts → станция → Hail в пределах **850 м** |
| Завершающий манёвр | Автоматический с облетом рельефа | Точное ручное наведение, затем автоманёвр |

Для станции необходимо одновременно выбрать landing site (а не случайный корабль/контакт), запросить clearance, вручную выровнять и замедлиться. `home.gd` на A, если условия не выполнены, в основном **показывает текст отказа**, а не запускает подходящий следующий шаг.

## 4. Единый UX: выбор цели → разрешение → подлёт → посадка [КАНДИДАТ]

1. **Выбрать остров/станцию** в 3D-атласе или Contacts. Глобальный `landing target` отдельный от текущего combat/inspect contact; простой осмотр другой цели не должен терять маршрут.
2. **Подлететь к станции в пределах 850 м:** в HUD `A · Request pad`. Короткое A выполняет hail/clearance (если орудия убраны, включены связь/сенсоры), без раскрывания вложенных меню. При отсутствии условий HUD показывает конкретное действие: выключена связь, убрать оружие, слишком далеко и т.д.
3. **Перейти на обычный полёт** из Cruise, войти в разрешённый коридор. В HUD видны расстояние до площадки, скорость, высота, permission и подход к точке входа. Короткое B включает стабилизацию/точную тягу; остановка LT остаётся универсальной.
4. **Финальная посадка — A · Dock/Land** при разумной дистанции, например в пределах **50–80 м** станции, если разрешение есть, оружие убрано, подход не перекрыт. Сам корабль гасит остаточную скорость, выравнивается и плавно доходит до платформы, **как уже сделано для островов**. Крупная скорость/небезопасный курс приводят к понятному сообщению, а не телепортации или столкновению.
5. **B в режиме автопосадки** отменяет манёвр, пока безопасно. Повторная посадка/выход из кресла не должны сбрасывать clearance произвольно. В районе станции движение при открытии меню не оставляет корабль на прямой тяге без контроля.
6. **После touchdown:** автоматически зафиксировать berth и системы; `A · Launch` только после посадки/из кресла; `B · Stand` и лифты для выхода на поверхность как раньше.

**Обязательное:** сохранить ручное маневрирование и опционально более сложную ручную стыковку в настройках для желающих, но по умолчанию дать Assisted Docking. Не автоматически запрашивать/оплачивать сервис и не менять экономику ремонта/топлива в рамках переделки управления.

**Разделять виды остановки:** `LT` — активный тормоз/реверс, `B short` — стабилизированное зависание/precision, `Cruise` — высокоскоростной режим, `Auto Dock` — конечный безопасный посадочный манёвр. Не допускать взаимоисключающих одновременных состояний.

## 5. Системная архитектура ввода

- **Один владелец контекста**: `Walking`, `PilotFlight`, `PilotArmed`, `PilotDockAssist`, `PilotPanels`, `PilotChart`, `PilotLanding`, `Pause`. Приоритеты и переходы заданы явно; не пытаться трактовать одинаковый InputEvent сразу в `helm_display._input` и `home._unhandled_input` как два независимых действия.
- Использовать semantic actions, их биндинги в одном месте, не мешать `decorate/confirm_place/rotate_left` с пилотированием. При повторном создании Ship Home не дублировать InputMap events.
- Учитывать Nintendo/Xbox/PlayStation/Steam input family для физической раскладки и HUD glyphs. `JOY_BUTTON_B` не означает буквальную кнопку «B» на Odin. Проверять кнопки по позиции/профилю, а не только надписи.
- Длительные нажатия B/Y/R3 отделить от коротких с корректной задержкой; «tap Y» не должен выбирать контакт после Y+look/другого chord, «B tap» не должен включать стабилизатор перед «B hold stand». Не создавать accidental X fire при переходе armed/unarmed на одном input.
- Вся точная тяга/flight assist остаётся физическим движением `flight.tick`, посадка — управляемой траекторией/коллизиями, а не мгновенным reset.
- При входе в панели и при вставании из кресла определять предсказуемое удержание позиции/постепенное торможение. Не возобновлять неожиданно старый throttle после закрытия меню.
- При потере ввода или отключении геймпада не удерживать навсегда ускорение или fire.
- Keyboard/mouse/touch сохраняют функциональность; подсказки переключаются по последнему устройству без путаницы.
- Поддержать настраиваемые раскладки позднее поверх семантического слоя; не копировать UI-модуль из оболочки без теста целевых устройств.

## 6. Минимальная проверка на настоящем железе

- Реально нажать каждую кнопку на **Odin 2 и Flip 2**, сверить семейство A/B/X/Y, направления стиков/триггеров, перехват системных клавиш, задержку B hold и R3.
- Со станции: посидеть → запустить → полностью остановиться → войти в precision → выйти из кресла → вернуться, без дрейфа в закрытый ангар.
- С острова: выбрать другой остров в том же кластере → свободный полёт → cruise/boost → точный подход → Assisted Land, включая 8 направлений, рельеф и край площадки.
- На станции: выбрать из атласа → подлететь на 850 м → A разрешение → отключить cruise/оружие → остановиться с 50–80 м → A автопосадка; повторить после отмены B.
- Проверить 6 станций и все 10 островов, collision/trajectory, снятие разрешения в нужный момент, сохранение точного причала, отсутствие повторного сброса при timeout.
- Проверить бой: hardpoints/lock/fire/weapon group, point defence, оружие не стреляет при посадке; переключения панели, свободного взгляда и слоёв ввода при движении.
- Проверить полёт с открытой картой/навигацией, переход из меню в cockpit, геймпад disconnect/reconnect, touch/mouse и фокус окна.
- Обновить тесты `experiences/ship-home/tests/flight.gd`, `avionics.gd`, `pilot_checks.gd`, `boarding.gd`, `tests/helm...` при новом дизайне; не принимать простой unit-test за физическую приёмку.
