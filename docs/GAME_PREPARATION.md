# Подготовка игр: BIOS, прошивки и паки

## Путь пользователя

Обычная сборка: **Start → Settings → Games & library → Library → Game preparation**.
Второй вход — **System health → Game preparation**. Экран общий для обычного
запуска и мультиплеера. L2/R2 меняют систему; touch и контроллер используют
одни действия. Слева — платформы; справа — только имена файлов, их состояние
и кнопки **Import**, без технических путей. Общая кнопка **Import BIOS pack**
с пояснением находится сверху. Требования многосистемных ядер распределены
по платформам: например, Sega CD BIOS не показывается в Master System.

Зелёная галочка означает наличие обязательных компонентов; красный крест —
отсутствие файлов или эмулятора; жёлтый треугольник — неполную/неописанную
подготовку. Online-сервисы Wii / 3DS / Wii U находятся **в той же правой панели**:
выбор сервиса, руководство, подтверждение подготовки и проверка.
Отсутствие проверенного входа в сервис сохраняет жёлтое предупреждение даже
при наличии всех файлов. Ручное подтверждение подготовки не является входом.

**Import** открывает общий `FilePickerController`; пользователь
не вводит путь назначения. Копирование выполняется в фоне, отображается в
общих Downloads и допускает отмену. Выход со страницы не прекращает импорт.
Игра, смена профиля, перенос библиотеки, сон и перезапуск не должны пересекаться
с этой записью. После импорта обновляются runtime и multiplayer, без нового
обхода ROM-каталога. Присутствие в Lobby не запускает игру.

## Пак одной операцией

**Import BIOS pack** распознаёт ZIP, 7Z и RAR по содержимому, независимо от
расширения. При выборе архива вместо отдельного BIOS он тоже распознаётся
автоматически, кроме совпадающего ожидаемого архивного BIOS вроде `neogeo.zip`:
такой файл нужен самому эмулятору в исходном виде.

Подбор делается по требованиям установленных ядер и описанных native-режимов.
Известные BIOS распознаются по контрольной сумме даже после переименования;
остальные — по точному имени и известному размеру. Подкаталоги пака учитываются.
Несколько идентичных копий допустимы; разные подходящие кандидаты не выбираются
по порядку. Необязательные компоненты не становятся обязательными, проверенные
названия игр не служат белым списком. Вложенные BIOS-архивы копируются как файлы,
произвольная рекурсивная распаковка вложенных паков не выполняется.

Итог показывает установленное, уже имеющееся, неиспользованные файлы и проблемы.
Совпадающие файлы пропускаются; отличающиеся уже установленные данные сохраняются.
В папках разрешено добавить отсутствующие файлы после проверки конфликтов.
По уточнению владельца исходный архив после полного успеха отправляется в
**корзину**. При ошибке, отмене, неоднозначности, смене исходника, неудачной
регистрации runtime или отсутствии подходящих компонентов архив сохраняется.
При недоступной корзине постоянное удаление не подставляется. Временная
распаковка очищается при любом штатном исходе; установленные до отмены компоненты
сохраняются и видны после повторной проверки.

Используется существующий `ArchiveExtractor` / libarchive. Ссылки, выход за
папку, специальные файлы, дубли путей и зашифрованные архивы не принимаются.
Лимит пака — 2 GiB исходного и распакованного содержимого; отдельного BIOS —
64 MiB, набора файлов — 512 MiB / 4096 файлов. Это ограничение импорта,
не совместимости игр. Большеразмерные контейнеры прошивок требуют отдельного
native-установщика и не объявляются BIOS после простого копирования.

## Реализованное покрытие и границы

- RetroArch: метаданные **342 ядер / 839 файловых требований** из
  [libretro-core-info](https://github.com/libretro/libretro-core-info), ревизия
  `445421549abc0638a2f5ecf05db8437e580dcc69`. На экране появляются установленные
  ядра, используются фактические `coresDirectory` и `system_directory`.
  [Генератор](../tools/generate-firmware-catalog.py) и
  [лицензия метаданных](../data/firmware/LICENSE) находятся в репозитории.
  Это не обещание поддержки всех этих эмуляторов TrainerOS.
- Sega CD: после появления всех трёх BIOS автоматически записываются
  `discFirmware.segacd` SHA-256; предыдущий профиль сохраняется рядом.
  Существующие отличающиеся отпечатки не заменяются молча.
- Nintendo 3DS / Wii U Online: импорт отдельных собственных console-файлов
  (OTP, SecureInfo, friend-code seed, SEEPROM, сертификаты) в реальные native
  каталоги, включая portable / Flatpak и настроенный NAND/MLC. Размер/наличие
  файла не подтверждает криптографическую пригодность или вход в сервис.
- Для неизвестных ядер нет ложного статуса «готово». Отсутствующие runtime
  показываются отдельно от файлов. Присутствие runtime не означает, что его
  полный список прошивок описан.

**Ещё не сделано:** универсальные рецепты всех standalone-эмуляторов, native
установка цельных Wii NAND / Vita PUP, Artic/Nimbus и вход в аккаунты сервисов,
проверка полноты native-наборов системных ресурсов. Их нельзя заменить копией
контейнера или галочкой «подготовлено». Этот экран и импорт файлов — основа
для следующих интеграций, не закрытие этих пунктов. BIOS, ROM, NAND, прошивки,
ключи и данные аккаунтов не включены в сборку и не загружаются из сети.

## Владельцы и безопасность

S03: `platform/emulation/GamePreparation` описывает требования и ограниченный
импорт; native Nintendo даёт свои требования через `NintendoOnline::requiredFiles`.
S15: `GamePreparationController`, общий picker и экран. S13: существующий
Downloads показывает работу, не выполняет второй независимый импорт.
S04: только вход, возврат и защита жизненного цикла. S08 и сейвы не меняются.

Одиночный файл сначала проверяется и копируется во временный файл на том же
носителе; публикуется без перезаписи. Проверяются размер, известная MD5,
совпадение копии с исходником по SHA-256, отмена и изменение назначения.
Консольные файлы/пути не попадают в Lobby, support export или сетевые запросы.
Локальный отчёт пака остаётся на странице и в задаче Downloads текущего запуска.
