# Блоки TrainerOS — отдельные описания

Здесь будут **самостоятельные Markdown-файлы**: один крупный блок = один документ. Каждый описывает продукт для человека, но опирается на код, ветку, устройство и доказательства. Перед созданием скопировать [_TEMPLATE.md](_TEMPLATE.md).

При аудите структуру разрешено дробить дальше. Пункты из `TARGET`, не доставленные в альфе, остаются обозначенными как перспективные, а не маскируются под действующие функции.

## Критерий «блок готов»

1. Понятно, **зачем он нужен игроку**, где находится и как работает.
2. Записаны реальные функции и короткий сценарий использования.
3. Подтверждены код/ветка/устройство/проверка, если заявлено, что функция уже работает.
4. Известные ограничения и зависимости не спрятаны.
5. Есть краткий абзац, который впоследствии можно использовать в публичной презентации.
