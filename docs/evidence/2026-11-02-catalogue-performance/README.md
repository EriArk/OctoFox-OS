# Одноразовое сканирование и отзывчивость оболочки — 2 ноября 2026

Уточнение владельца: важна **одноразовость**, а не только видимость сканирования.
Основной стенд — Flip. Odin используется для доставки и короткой проверки запуска;
нагрузочные прогоны его проблемной microSD не проводятся.

## Пользовательский результат

- Settings → Library → Library scanning: один проход при запуске (по умолчанию)
  либо Manual only. Scan library now запускает отдельное ручное обновление.
- Games, Home, Recent, возврат фокуса и минутный опрос runtime больше не запускают
  обход ROM. Запросы во время текущего обхода не создают следующий проход.
- Между запусками сохраняются каталог, доступность и оформление игр. В ручном
  режиме внешние изменения файлов появляются после Scan library now. Запуск игры
  по-прежнему проверяет настоящий файл и runtime; кеш не разрешает операции с saves.
- Явная смена корня, перенос ROM и завершение выбранной пользователем пачки
  ScreenScraper обновляют каталог. Избранное обновляет свою запись без обхода.
- Старые снимки проверяются после открытия профиля отдельным работником. Home
  сначала может показать обложку; неподтверждённый снимок не публикуется.

## Найденные причины

| Участок | Исправление / граница |
|---|---|
| Навигация → refreshContentAvailability → отложенный rescan | Удалены неявные запросы и очередь повторного обхода; сохранён явный запуск. |
| Загрузка SQLite → stat каждого ROM | Последняя доступность хранится в SQLite, обновляется при явной проверке. |
| Загрузка профиля / правка библиотеки → хеширование ROM ради exit media | Первичная проверка отделена от opened; последующие чтения используют проверенные session ID и актуальные ограничения БД. Защита записи снимка не ослаблена. |
| Импорт большой библиотеки в GUI | Обработка уступает циклу событий после 4 мс; файловый обход и запись кеша выполняются вне GUI. |
| Скрытые Recent / Home / Journey / achievements | Убраны запросы полного представления из невидимых панелей и повторное получение одного Home-результата. |
| Минутный таймер → полный multiplayer refresh | Убрана дублирующая связь Main. Собственный dependency watcher, изменения runtime/библиотеки и проверки допуска сохранены. |
| Multiplayer content identity | Отдельный фоновый механизм, не ROM discovery. Полное вычисление identity при запуске и синхронная подготовка refresh остаются; протоколы и проверка точного содержимого этим core-проходом не переписываются. |
| Images / Browser / Files / processes | Сохранены существующие async images, виртуализация списков, фоновые файловые операции и жизненный цикл Browser. Ожидание завершения helper в деструкторе Apps не является операцией переключения вкладки. |

## Проверки и поставка

Проверены 1541 входной файл общей ARM64-сборки. Восемь наборов QtTest дали
**182 passed, 0 failed, 1 skipped**; пропуск — сценарий переодевания без avatar
pack в изолированном контейнере. Отдельный повтор Core проверил новый тест после
коррекции mtime при доставке delta-исходников; production-бинарник не менялся.
[Машиночитаемые результаты](validation.json). Исправлены устаревшие ожидания
двух фикстур: версия схемы 14 и отсутствие поддержки самостоятельного PS1 BIN
(последняя добавлена в manifest ещё 25 октября). Runtime discovery из-за этих
ожиданий не изменялся.

Production `BUILD_TESTING=OFF`, SHA-256
`2a8beeef2c03597b9287554473dd52a1286512c08638c076c92184dfcf7a2247`
**установлен и запущен на Flip и Odin**. На обеих просмотрен настоящий Home,
ошибок QML в журналах новых процессов нет. Сохранены прежние строки защищённых
таблиц, настройки, avatar pack и hashes интеграционных helpers; SQLite quick_check
прошёл. Odin оставлен с нулевой громкостью, Flip — с прежними 20%.
[Квитанции без частных путей](delivery.json). Резервные binary/settings/SQLite
остались в каталогах доставки; сборочная среда находится на microSD Flip.

На Flip startup scan завершился один раз. После маршрута вкладок и Recent
число завершённых обходов осталось **1**. На старом процессе до установки было
9 проходов за startup и навигационные проверки. Обе версии сообщали о двух
записях с невалидным названием/изданием; эти прежние ошибки импорта не скрыты
и записи не исправлялись произвольно. На Odin также завершён один startup scan,
и прежнее ожидание профиля в этом запуске не повторилось. Это не ремонт карты.

Сравнение Flip: три цикла Home/Games/GameHub/Online/Apps и Recent, по 18
переключений страниц, без одновременной сборки. Запросы Home: 1206 → 644,
Continue: 161 → 17; среднее время обработчика перехода: 287 → 173 мс.
**Это наблюдения, не изолированный benchmark:** владелец сообщил о параллельной
работе NGPC-чата. Первый новый прогон был остановлен проверкой активного окна
и исключён; следующий завершил все 18 переходов. Трасса не измеряет touch-to-photon
или гарантированный FPS. [Метрики и оговорки](performance.json).

После сообщения владельца автоматический ввод и перезапуски остановлены, чтобы
не мешать NGPC. Созданный этим проходом trace-флаг удалён без перезапуска чужой
проверки; текущий процесс отключит трассировку при следующем обычном запуске.
**Осталось:** в живом Settings выбрать Manual only → перезапустить → убедиться
в отсутствии startup scan → Scan library now → проверить ровно один проход →
вернуть выбранный режим. Логика режима/кеша уже проверена фикстурами; это не
подменяет оставшийся установленный UI-цикл.

Регрессии покрывают отсутствие обходов при навигации, отсутствие второго прохода
при повторных запросах, восстановление метаданных/избранного без ROM-дерева,
сохранение доступности, порядок opened/optional media и прежние проверки
принадлежности/ревизии/изменённого ROM/Steam build для снимков.

SQLite переходит с версии 17 на 18: добавлена только сохранённая доступность.
Старый бинарник не умеет читать схему 18. Для отката нужны согласованные резервные
копии бинарника и базы; восстановление старой базы поверх более позднего прогресса
не выполняется автоматически. Сохранения, аккаунты, кошельки и runtime-пакеты
не заменяются.

Глубокая физическая приёмка, длительный прогон и ремонт накопителя Odin остаются
отдельными. Успешные фикстуры не доказывают эти условия.
