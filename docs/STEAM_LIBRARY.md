# Библиотека Steam — #69

Владелец: S02 (игры и их идентичность), S03 (наблюдаемая игровая сессия),
S15 (установленные helpers). Steam сохраняет магазин, загрузки, обновления,
Proton, облачные сохранения и Steam Input. TrainerOS не изменяет его конфигурацию,
учётные записи, игровые файлы или историю Steam.

## Входы и возврат

- Запуск TrainerOS или Settings → обновление библиотеки: фоновое чтение известных
  каталогов Steam и `libraryfolders.vdf`, затем манифестов установленных приложений.
- Games → Steam → игра: та же карточка и выбор для Home, что у других игр.
- Home/карточка → запуск: штатный клиент Steam открывает App ID. Настройки питания
  TrainerOS применяются прежней сессионной арендой; Proton и Steam Input остаются
  у Steam. Дублирующий mapper TrainerOS для этой сессии не включается.
- Home во время игры → прежние Game Options / сворачивание / возврат / выход.
  Выход запрашивает закрытие конкретного окна игры; клиент Steam не закрывается.
- После завершения возвращаются прежний экран и фокус. Время TrainerOS начинается
  только при наблюдаемом окне игры, а не при запуске команды `steam`.
- Start → переход в Steam остаётся отдельным входом в полное окружение для
  управления установкой. Перенос и удаление Steam-файлов из TrainerOS запрещены
  и на уровне меню, и на уровне операции библиотеки.

## Идентичность и чтение

`steam:<AppID>` сохраняется при переносе, отключении диска и переустановке.
Регистрация хранит root клиента, root и content ID библиотеки, путь манифеста,
каталог установки и наблюдаемую доступность. Отсутствующая игра не удаляется
из истории. Повторный импорт сохраняет пользовательское переименование.
Две установки одного App ID дают недоступную запись с объяснением; порядок
обхода каталогов не выбирает установку. Отсутствующий/повреждённый кэш типов
не превращает Proton или Steam Runtime в игры: импорт ждёт обновления Steam.

Читаются ограниченные по размеру KeyValues и appinfo 27/28/29. Типы Game/Demo/Mod
берутся из `common/type`; названия не используются для определения типа.
Обложки, логотипы и фон читаются только из известного локального `appcache/librarycache`;
разработчик, издатель и дата выпуска — из локального appinfo. Для Steam есть
собственная плитка платформы; карточка использует общие варианты отображения Games.
Ни LastPlayed, ни время Steam не импортируются в историю TrainerOS.

Формат appinfo сопоставлен с [описанием ValvePython](https://github.com/ValvePython/steam/blob/master/steam/utils/appcache.py);
код чтения ограничен нужными локальными полями, сторонний пакет не устанавливается.
Запуск использует `steam -applaunch <AppID>`; завершение этой команды не является
завершением игры — это также [зафиксировано в upstream Steam](https://github.com/ValveSoftware/steam-for-linux/issues/6123).

## Наблюдение и ограничения

Снимок при выходе привязан к App ID, build ID, каталогу установки и регистрации
профиля. Изменение Steam-полей LastPlayed/загрузок не считается заменой игры;
смена build ID, регистрация другой установки и повреждённый манифест отклоняют
старый снимок для Home. Архив фотографий и история сохраняются. Этот ограниченный
presentation fingerprint никогда не используется как допуск к чтению/записи save.

Supervisor принимает только новую группу процессов точного App ID текущего
пользователя. Уже работающий экземпляр не присваивается новой сессии. Для PID
проверяется время старта; при переподчинении сохраняются наблюдавшиеся потомки.
Оверлеи используют XRes PID окна и ту же ограниченную группу. Окно Steam,
другие игры и повторно использованные PID не получают права на ввод или выход.
Состояние наблюдения находится в приватном runtime-каталоге и удаляется после
сессии. Не используются названия окон, глобальное завершение Wine или Steam.

Steam может сначала потребовать вход, выбор режима, обновление или установку
совместимости. Если игровое окно не появилось за 120 секунд, TrainerOS сообщает
об этом и не записывает сыгранную сессию. Ожидающий запрос/диалог самого Steam
может потребовать действий в клиенте: общий клиент не завершается принудительно.
Проверенная интеграция не означает совместимость каждой игры с ARM/FEX/Proton.
Wayland-only игры без Xwayland/XRes пока не имеют принятого цикла Home/выхода.

## Проверки и поставка

Исходные проверки включают повреждённые/неоднозначные манифесты, типы приложений,
перенос и исчезновение библиотеки, недоступную установку, повторное использование
PID, переподчинение потомков, отложенный/разбитый по чтениям сигнал запуска,
отсутствие ложного старта, сохранение идентичности и запрет удаления манифестов.

1 ноября production-сборка установлена на Odin/Flip: Games/Home, настоящие
Dead Cells на Flip и Celeste на Odin, Game Options, выход, история и снимки
проверены. На Flip также пройдены Minimize и возврат в ту же игру.
[Сборка, тесты, найденный дефект и фактическая поставка](evidence/steam-library-20261101/README.md).
Физические кнопки, длинная игра, облачная синхронизация, Flatpak и
совместимость остальных игр остаются отдельной приёмкой.
