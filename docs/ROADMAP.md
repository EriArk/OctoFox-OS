# Глобальный план снят

**4 ноября — Setup получает закреплённые оригинальные пакеты автоматически.**
Добавлены проверенные upstream AppImages, 10 точных Flathub commits и Vita3K
без перепаковки его runtime; наши мультиплеерные компоненты, PPSSPP и прежний
Dolphin сохранены в комплекте. Cemu закреплён на проверенной стабильной 2.6-4.
Исходники и тесты готовы; новый полный цикл на Flip и публикация ещё впереди.
Это не заменяет приёмку прежнего Software 9/runtime 16.
[Реальные загрузки, проверки и порядок выпуска](evidence/2026-11-04-upstream-installer/README.md).

**4 ноября — чистый цикл Setup пройден на Flip.** Production-signed Software 9 /
runtime 16 (`77d12791`) установлен одним процессом из пустого private root, без
ручного ремонта и повторного запуска. Кнопка Setup открыла standalone-сессию;
мастер → Home → NES Pong → штатный выход → Restart → автоматический Home пройдены.
76 cores, 6 Python environments и 12 private Flatpak refs проверены. До сброса
проверены обычный откат 8/15 → 7/14 и удаление; 36 личных файлов сохранились,
прежние профили отложены с проверенной копией. Odin не менялся.
Это приёмка установки, не физическая/сетевая сертификация всех игр.
Публичная загрузка GitHub и финальные source/notices ещё в работе; релиз не опубликован.
[Доказательства](evidence/2026-11-04-installer-final/README.md).


**4 ноября — Flip восстановлен, установка аватарного кандидата завершена; финальный установщик в работе.**
После перезагрузки действующие Software 7/runtime 14 сохранились. В промежуточных
Python-окружениях melonDS/RMG отсутствовали файлы при сохранённых отметках готовности;
они пересозданы из закреплённых offline-входов. Точная причина зависания не установлена.
Затем обычный GUI установил Software 8/runtime 15: оба аудита `ready`, 76 cores и
19 recovery blobs сверены, 31 личный файл из baseline после перезагрузки совпал.
Home отдельной сессии, профиль, гардероб и анимация аватара проверены.
**Этот проход с ручным восстановлением не является приёмкой чистой установки.**
В исходниках Setup добавлены ограниченное восстановление неактивированной подготовки
и переход прямо в отдельную сессию после установки; 59 Linux-проверок прошли.
По последнему поручению владельца следующий обязательный результат — финальный пакет,
чистый цикл «скачал → один запуск → установил → пользуйся» без ручного ремонта/крашей,
проверка восстановления и затем публикация GitHub/OTA. Личные данные сохраняются;
Odin не меняется. Публичного выпуска пока нет.
[Проверки и состояние](evidence/2026-11-04-avatar-resources/README.md).


**4 ноября, текущий этап:** [VirtualJaguar и вложенные исходники](evidence/2026-11-04-release-source-repair/README.md)

зависимости и notices, затем финальный публичный комплект и GitHub/OTA.
Полный каталог игр и все сетевые режимы не становятся gate альфы. Старый
VirtualJaguar dirty diff не восстановлен: вместо него установлена новая сборка.

## Текущий выбор владельца — пре-бета и отдельная сессия, 3 ноября 2026

Позднейшее уточнение: альфа выпускается с явно указанным неполным функционалом.
Завершение всех платформенных режимов не блокирует выпуск. Подготовка уже
работающих маршрутов в Setup и сохранение пользовательских данных обязательны.

Установщик размещает собственные эмуляторы рядом с пользовательскими и выбирает
отдельную сессию TrainerOS по умолчанию при первой системной интеграции. На Flip
проверены настоящая перезагрузка, возврат в Desktop и входы в сервисы; полный
кандидат собран, публичного выпуска пока нет. ScreenScraper application access
и hybrid Setup доставлены. Следующие оставшиеся пункты — завершение source/license
комплекта и GitHub release/OTA. [Текущее состояние и границы проверок](CURRENT_TASKS.md).
Транспорт большого Setup частями и три новых source capsules подготовлены;
[результат](evidence/2026-11-03-release-delivery/README.md) не означает публикацию.
Для 58/76 старых cores собраны inputs; для остальных 18 теперь [собраны отдельные
кандидаты с известными исходниками](evidence/2026-11-04-core-rebuild/README.md). Следующий
шаг — private RetroArch на Flip и продвижение проверенных замен в Setup, затем
оставшиеся материалы/модели и GitHub/OTA. Старый набор пока сохранён.

**Решение владельца, 21 октября 2026:** глобальные планы, этапы и обязательная
очередь больше не используются. Работа временно ведётся по готовности функций.

Единая [карта готовности с галочками](FEATURE_READINESS.md) сохраняет сделанные,
недоделанные, несделанные и непроверенные части. Требования остаются в профильных
[issues](https://github.com/EriArk/TrainerOS/issues) и технических документах.
Порядок строк карты не является планом исполнения.

Прежние последовательности из ROADMAP, AGENTS, issues и датированных отчётов
не задают следующий этап. Сохраняются требования, реальные зависимости,
результаты проверок и ограничения реализации. Категории «отложено» нет.

Этот файл оставлен как указатель для существующих ссылок. История планов
доступна в Git; новый глобальный план без решения владельца не создавать.
