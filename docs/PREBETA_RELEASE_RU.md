# Пре-бета: подготовка выпуска 3 ноября 2026

Владелец поручил подготовить публичную пре-бету: установку поверх Armada,
Software OTA преимущественно с GitHub и актуальную базу для образа/установщика.
Это текущая работа в main. Ранее оставленная другому чату установка больше не
исключена из этого прохода. Номер кандидата — **0.1.0-prebeta.1**, канал **Preview**.
Кандидат не означает состоявшийся публичный выпуск.

## Состав и владельцы

- Software S: приложение, встроенные ресурсы, общий avatar pack, библиотека Files,
  помощник захвата, Setup/Recovery и собственные интеграции. Вход — проверенный
  подписанный пакет; выход — owned receipt и отдельная сессия. Владелец S13,
  потребители S04/S15/S08; договоры #119/#123/#154.
- Armada H/I: отдельная база Linux, загрузчик, ядро и драйверы. Установщик Software
  не форматирует диск и не вызывает обновление host OS.
- Crates G, пользовательские игры/BIOS/сохранения/аккаунты и частные art packs
  не входят в заменяемое содержимое Software.
- Дополнительные эмуляторы требуют полного release inventory. Работа вручную
  подготовленной портативки не доказывает их наличие у нового пользователя.

## Исправленные проблемы первого пакета

1. В Setup отсутствовали PC helpers, которые читал session installer. Bootstrap
   включает три используемых файла и отвергает неполный архив.
2. Журнал root-owned файлов не разрешал эти три собственных PC-пути. Добавлены
   точные разрешённые пути; произвольные соседние файлы не принимаются.
3. Preview, выбранный в Setup, терялся при первом старте оболочки. Выбор сохраняется
   в установке и передаётся launcher; явное предпочтение пользователя имеет приоритет.
   Архив Preview предлагает Preview по умолчанию.
4. `GNUInstallDirs` подключался после первого install rule. Теперь все ресурсы,
   включая профильные аватары, попадают внутрь выбранного prefix.
5. [payload.py](../packaging/software/payload.py) выполняет CMake install
   из native builder и добавляет точные `libfm-qt6` и `libmenu-cache` с лицензиями RPM.
   Он не собирает файлы из домашнего каталога игрока и не разрешает публикацию
   автоматически. Capture helper требует `pipewire-devel` в builder.
6. Setup содержит клиент Crates, launcher, bootstrap registry и закреплённый
   ключ каталога. Системная установка записывает эти пять точных файлов в журнал
   ownership; пакеты, receipts и личные данные Crates в него не входят.
7. Общая установка сессии включает Wi-Fi/Bluetooth/Nearby helpers и прежние узкие
   sudoers-права. Radio installer теперь принимает общий writer: все пути проходят
   managed preflight до первой записи, repair/uninstall используют тот же журнал.
   Установка не переключает радиомодули и не меняет сохранённые сети.

Проверки распаковывают настоящий Setup archive и исполняют подготовку списка
session helpers из него, вне development checkout. Linux-тесты проверяют
подписи, HTTPS/Range, повреждения/прерывание, восстановление, совместимость
отката, блокировку активного runtime и сохранение личной базы.

**Проверено:** 73 Python-проверки на Linux ARM64 и 20 результатов QtTest (включая
инициализацию/завершение) без ошибок. Production с `BUILD_TESTING=OFF` собран.
В чистом закреплённом OCI Armada, без сети и каталогов игрока, оба ELF разрешают
зависимости; обычный первый запуск приложения подтвердил первый отрисованный
кадр, stderr пуст. Первоначально отсутствовавший `libmenu-cache.so.3` исправлен
в составе пакета. Это offscreen-проверка, не проверка GPU, браузерных сайтов,
открытого GLB или новой физической сессии. Личные установленные ОС не обновлялись.

## Выбранная Armada

На момент проверки последняя опубликованная preview — **20261102.d4f6880**,
исходники `d4f6880011652dc25522138f17f5c3c4cb5d3aae`, ядро `7.2.14-200.fc44.aarch64`.
Это preview, а не последний stable tag. Контейнер закреплён по digest, образ —
по опубликованному SHA-256 в [armada-base.json](../packaging/image/armada-base.json).
Источники: [официальный каталог](https://downloads.armadaos.dev/preview),
[исходники базы](https://github.com/armada-os/armada/tree/d4f6880011652dc25522138f17f5c3c4cb5d3aae).

OCI-проверка не является загрузкой нового ядра на устройстве. Собственный
готовый к прошивке образ TrainerOS и clean-flash acceptance отсутствуют;
исходный образ Armada нельзя выдавать за готовый образ TrainerOS.
Для первой установки основной путь — Setup поверх поддерживаемой Armada.

## Подпись и публикация

[Публичный ключ](../packaging/software/trusted-release-key.pem), SHA-256 PEM:
`fbb51711bcaaae03c0afc2a45648af1fe7b08a8d4d15e348cd9a7d8a66ae7cd2`.
Закрытый ключ хранится отдельно с доступом только владельца; он не входит
в Git, Setup, образ, контейнер сборки или журнал. Резервное хранение и ротация —
операторские операции, не загрузка нового ключа из OTA feed.

Публичная схема, поддержанная publisher:

1. Immutable prerelease tag: `TrainerOS-Setup.tar.gz`, `traineros.tar.gz`,
   `release.json`, corresponding source, лицензии и build provenance.
2. Проверка анонимного скачивания опубликованных байтов с GitHub Releases.
3. Подписанный `preview.json` в ветке `updates` публикуется **после** доступности
   assets. Beta не объявляется готовой из-за наличия Preview.
4. Settings → System → Updates: отдельные проверка версии, скачивание и
   подтверждение применения. Активная игра/защищённая операция удерживают замену.
5. Предыдущая совместимая Software-версия остаётся для явного возврата. Личная
   база не откатывается; несовместимые схемы запрещают возврат.

Feed имеет срок до 31 дня; оператор обновляет подпись/sequence даже при прежнем
пакете. Истечение feed не удаляет установленную версию. GitHub Actions остаётся
отключённым. Подготовленный ключ не означает опубликованные feeds.

## Незакрытые условия выпуска

- Публичная раздача общего аватара требует закрыть конкретные записи
  [asset provenance](../assets/avatar/README.md): исходное тело и CGTrader hair.
  Согласованный внешний вид не заменяет отсутствующие условия распространения.
  `publisher` по-прежнему требует подтверждённый redistribution review.
- После проверенного первого кадра в чистой Armada остаются браузер, avatar importer
  и привилегированная интеграция. Ни `ldd`, ни первый кадр не доказывают все экраны.
- Bootstrap/root helpers пока не обновляются application OTA. Нельзя объявлять
  приложение новым полным Software S при несовместимых старых helpers;
  их версионирование/обновление остаётся частью #119/#123/#154.
- Ручная установка на личных Flip/Odin не присваивается managed installer молча.
  Нужна отдельная проверенная миграция с восстановлением.
- Voice/runtime helpers ещё используют отдельные процедуры установки. Наличие
  capture ELF внутри пакета не заменяет их регистрацию/зависимости и сетевую приёмку.
- Чистая установка, вход/выход, repair/uninstall и возврат Steam/Desktop остаются
  отдельной приёмкой. ROMs/сохранения владельца не удаляются ради такого теста.

Это условия конкретного выпуска, а не новая глобальная очередь разработки.
