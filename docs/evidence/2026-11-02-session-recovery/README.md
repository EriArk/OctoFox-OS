# Восстановление серверного входа — 2 ноября 2026

## Причина и изменение

На Flip и Odin защищённое хранилище содержало старый `pending` без refresh token.
Это подтверждает незавершённую ротацию, но не устанавливает конкретную причину
потери первоначального ответа: соответствующего сетевого журнала нет.
Прежний протокол намеренно удалял credential перед однократным запросом и
не мог восстановиться после обрыва или завершения процесса.

S04 BackendAccount теперь атомарно сохраняет зашифрованный журнал версии 2:
исходный token и случайный recovery proof. S01 Accounts разрешает повтор
именно этой операции, возвращая ту же пару credentials. Сервер хранит хеши,
а не исходные секреты. Access восстанавливается в пределах прежнего абсолютного
срока сессии; отменённая/истёкшая сессия и приостановленный игрок не допускаются.
Другой proof или повтор без proof по-прежнему отзывают сессию. Точный поздний
повтор уже завершённой старой операции не отзывает более новую ротацию.

При временных сетевых/серверных ошибках и ошибке сохранения клиент повторяет
операцию через 2–60 секунд; ручной Retry использует тот же журнал, одновременно
работает только один запрос. По уточнению владельца серверный профиль остаётся
основным и после офлайн-перезапуска: защищённая запись хранит последнюю проверенную
identity, существующий кэш — имя/прогресс/баланс с проверкой владельца. Баланс
помечается устаревшим. Кэш не выдаёт свежую серверную сессию и не разрешает
покупки/SDK grants. Явный выход/смена аккаунта очищают этот выбор; потеря сети и
истечение сетевой сессии — нет. Игра не получает credentials.

Старый `pending` без token не восстанавливается этим протоколом: для него нужен
один обычный OAuth через существующий аккаунт. Это миграция старого состояния,
а не предложенный способ лечения будущих обрывов. Личный Patreon не привязывается,
новые игроки/Искры не создаются.

## Проверки и сервер

- Полный Backend suite в отдельной PostgreSQL на существующем сервере:
  **161 passed**, одно прежнее предупреждение Starlette/httpx.
- Новые случаи: потерянный ответ и новый экземпляр сервиса, concurrent retry,
  истёкший access без продления срока сессии, неверный/отсутствующий proof,
  superseded retry, expired/suspended, HTTP validation и `no-store`.
- ARM `backend_account`: **41 passed, 0 failed, 1 skipped**. Пропуск относится
  к Windows vault. Проверены журнал до HTTP, повтор после перезапуска,
  автоматический/ручной повтор, запрет параллельной ротации, ошибка сохранения
  ответа без отзыва и отсутствие цикла после постоянного отказа. Дополнительно:
  основной серверный профиль после офлайн-перезапуска, устаревший баланс,
  запрет выдачи онлайн-доступа по кэшу, изоляция владельцев/непроверенного кэша,
  сохранение профиля при истечении сессии и очистка при явном выходе/смене.
- На живом Backend применена миграция 15 и образ `traineros-backend:refresh02`.
  API/worker healthy; анонимные profile/progression/support возвращают 401.
  Снимки identity, progression, reward ledger, покупок, owned items, outfits/slots,
  призов/полки и support links до/после установки совпали.
- Публичный HTTPS также проверен: health live/capabilities 200, внутренние
  ready/OpenAPI 404, анонимный `/v1/me` 401. Проверочный скрипт обновлён под уже
  существующие capabilities прогресса/покупок/профилей и POST-only покупки (GET 405);
  сам API этих возможностей в этом проходе не менялся.
- Перед обновлением сохранён закрытый dump БД и подготовлен совместимый со
  схемой 15 fallback image. Старый образ без новой migration history не считается
  корректным откатом после миграции. Секреты и backup не публикуются.

## Портативки и границы

Production-сборка Qt 6.11.2/aarch64 установлена на обе портативки:
`ae63803d59c18672fc8cebce5f7f918e0ebb3762b32b49c15f7e6be3564e8ee5`.
Основа исходников — `cce39034` плюс изменения Accounts этого прохода;
1533 файла сборочного manifest совпали с исходниками перед фиксацией.
Параллельный `5627e9b1` (NeoCD/NGPC) поступил после сборки: сохранён при
объединении main, но его доставка не заявляется этой проверкой Accounts.
На Flip/Odin выполнен обычный OAuth с сохранёнными Mika/Ren, затем обновление
клиента и реальный refresh при запуске. На Home видны прежние имена, уровень 1
и 100 000 Искр. Новых identity или начислений нет; снимки серверных привязок,
кошелька, покупок, образов, призов и Patreon совпадают с исходными.
Базы SQLite прошли quick_check; существующие защищённые строки, настройки,
аватар-пак и интеграционные помощники сохранены. Громкость: Flip 20%, Odin 0%.

Во время установки на Flip supervisor ожидал оставшийся дочерний Firefox после
завершённого OAuth. Его штатное закрытие освободило ожидание; новая оболочка
запустилась. На Odin окно входа закрыто перед заменой бинарника. Перезагрузка
устройств и изменение политики supervisor не потребовались.

На каждой портативке временно заблокирован HTTP/HTTPS приложений с сохранением
служебного SSH, затем перезапущена оболочка. Home сохранил Mika/Ren, уровень 1
и 100 000 Искр; профиль показал `Last confirmed balance · offline`. Защищённая
identity совпала с владельцем кэша, pending-журнал содержал token/proof версии 2.
После снятия ограничения обе сессии восстановились автоматически, без кнопки
Retry и нового входа: pending очищен, в профиле снова `Available balance`.
Временные правила удалены; Backend доступен. Сервер подтвердил 3 восстановимые
ротации Mika и 2 Ren; все перечисленные защищённые таблицы остались неизменными.
Это реальная потеря сети до запроса и перезапуск процесса; потерянный ответ после
commit проверен тестами, а не инъекцией сбоя на живом аккаунте. Многодневное
удержание входа и физическая перезагрузка устройства здесь не заявляются.
Общая сборка сохраняет main с Doom/Model 3; отдельные runtime-пакеты и помощники
другого потока не заменяются этой поставкой. Физическое управление отдельно.

microSD Odin по прямому решению владельца снова подключена для записи;
привычная задержка не блокирует продолжение. Ошибочный DISCARD отключён.
[Ремонт, очистка и уточнение владельца](../2026-11-01-account-identity/README.md).

Открытые общие границы Accounts: push revocation, удаление/смена привязки,
очистка credentials при удалении локального Trainer и auth retention.
Они не закрываются этим исправлением refresh.
