## Проверочная среда

Объединённая ARM Release-сборка выполнена на microSD Flip в отдельном каталоге,
с проверкой SHA-256 входящих исходников. UI-сценарии запускаются в контейнере
с изолированными данными, без сети, с offscreen/software renderer. Общий пакет
аватара подключён только для чтения; личные рецепты и базы пользователя не
подключены. Это проверка QML/навигации, не проверка GPU-рендера на экране.

Первый запуск Online остановлен на ожидании отсутствовавшего в контейнере
пакета аватара. После добавления read-only mount сценарий повторён полностью;
проверки гардероба не исключены. Первые логи/кадры сохранены отдельно.

### Нагрузка и обнаруженное отдельное недоделанное поведение

12-секундные whole-process выборки Flip без компилятора: прежние Home 100,33% /
Apps 12,92%; новые Home 73,92% / Apps 38,92% одного ядра, повтор Apps 36,50%.
**Сравнение ускорения недостоверно:** после рестарта параллельно шла проверка
идентичности игровых образов мультиплеера. Pooled worker потреблял 25,75% одного
ядра, QSGRenderThread в Apps 0,25% за 8 секунд. Открытые дескрипторы указывали на
GDI/CUE и большие BIN/IMG; read_bytes процесса превысил 50 ГБ. Снимки не доказывают,
что переключение вкладок повторно запускает этот проход.

Точный источник: `RuntimeMultiplayer::refresh` ставит все подходящие регистрации
в `pending`, затем вызывает `runtimeIdentity`; результаты `scanResults_` хранятся
в памяти. `NetplayDigestCache` также worker-local; `fileDigest` читает весь файл
порциями по 64 КиБ для SHA-256. После рестарта эти кэши пусты. Это отдельная
стоимость поиска совпадающего контента, а не необходимость определения региона.

После вопроса владельца принято различать быстрое определение ID/версии/региона
и точную проверку данных конкретной сетевой сессии. Массовое хеширование на старте
нужно убрать; изменение этого пути **ещё не реализовано этой поставкой**.
Сохранение кэша само по себе не устраняет первый полный проход. Требуется
проверка по запросу выбранной сессии без исчезновения игр из Lobby/Invite и без
ослабления проверки перед сетевым запуском. Это основной следующий разбор.
Также обнаружено перекрытие длинным статусом нижнего пункта Games & library;
вход в подготовку игр работает, геометрия статуса остаётся незавершённой.
