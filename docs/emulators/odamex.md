# Doom — штатный мультиплеер Odamex

Реализовано и установлено на Flip 1 ноября 2026, R049. Владелец подтвердил продолжение Doom после Model 3. Odin и его накопитель оставлены владельцу для проверки карты;
это не задача диагностики или восстановления накопителя в этом чате.

## Выбор движка

Используется [Odamex](https://github.com/odamex/odamex), revision
`3a763534ac609aee8d22351baa3155809c4ea355` (12.3.0), без изменений игрового
протокола. Его штатный сервер выполняется на устройстве организатора,
клиент — у каждого участника. Upstream предоставляет prediction/interpolation,
компенсацию задержек, контроллеры, Doom/Boom/MBF21 и ряд расширений.
Это не совместимость с любыми модами GZDoom/ZScript.

Сравнение: [Chocolate Doom](https://www.chocolate-doom.org/wiki/index.php/Multiplayer)
имеет готовую сеть, но сохраняет ограничения vanilla; для широкого набора
карт выбран Odamex. GZDoom/Zandronum остаются отдельными несовместимыми
движками, не вторым автоматически включённым протоколом. Не создаётся
новая синхронизация Doom в TrainerOS.

## Вход, сеанс и возврат

S03 `DoomNetplay` и `StandaloneAdapter` → S06 обычный Online Lobby →
Seats / Ready / явный Start организатора → S07 существующие ICE/DTLS
`cabinet`-соединения → native UDP Odamex → обычные Game Options / Home / Exit.
Nearby использует тот же путь с локальными кандидатами. Интернет использует
существующий прямой транспорт; сложные NAT остаются его ограничением.
Ни отдельный VPS, ни ввод IP, ни настройка VPN игроками не требуются.

Поддерживается 2–4 участника в соответствии с текущим общим контрактом мест.
Это лимит интеграции Lobby, а не лимит Odamex. Присутствие в комнате и возврат
в неё не запускают игру. Вход в уже начавшийся сеанс через TrainerOS пока не
заявлен, хотя у самого движка есть динамические подключения.

У каждого сеанса приватное сетевое пространство. Гостевой UDP-прокси принимает
один локальный клиент; на хосте каждый гость получает отдельный локальный UDP
адрес. Через канал идут только ограниченные датаграммы, без удалённо заданных
адресов или команд. Сохраняются границы пакетов, ограничиваются очереди и
длины. Разрыв закрывает сетевые прокси и принадлежащий сеансу сервер;
окно игры остаётся игроку. Выход клиента останавливает сервер и прокси.
Родительская привязка процессов исключает оставленный сервер после аварии.

`cabinet` — существующий надёжный канал. Он не становится нативным
ненадёжным UDP: потери могут задержать последующие датаграммы. Проверки
доставки пакетов не являются обещанием отсутствия лагов в любой сети.

## Файлы и совместимость

Платформа `doom`, каталог `doom`, расширения `.wad` и `.doom`.
Самостоятельный IWAD можно выбирать прямо. Набор с PWAD/DeHackEd задаётся
неисполняемым JSON-файлом `.doom`; пути относительны к нему, порядок важен:

```json
{
  "version": 1,
  "iwad": "base.wad",
  "files": ["maps.wad", "extras.wad"],
  "deh": ["changes.deh"],
  "mode": "coop",
  "map": "MAP01",
  "skill": 3
}
```

`files`, `deh`, `mode`, `map`, `skill` необязательны. Режим `coop` или
`deathmatch`; сложность 1–5, начальная карта из выбранного набора (имя lump до восьми букв, цифр или `_`).
Не передаются произвольные аргументы или консольные команды.
Самостоятельный PWAD требует явного базового IWAD; подстановка по названию
или соседнему случайному файлу запрещена. Внешние BEX `include` пока требуют
самодостаточного патча: скрытые зависимости не могут проходить как совпадающий
набор. PK3/ZIP и GZDoom-only моды не заявлены этим маршрутом.

Допуск не содержит списка названий или проверенных игр. Проверяются структура
WAD, доступность зависимостей, SHA-256 всех файлов в порядке загрузки, режим,
карта, сложность и версия сетевого пакета. Переименование/перемещение одинакового
набора не меняет его идентичность. Перед запуском проверка повторяется.
Наличие подходящего формата не сертифицирует конкретную карту или мод.
Встроенные загрузчики отсутствующих WAD отключены; каждому нужен свой набор.

## Данные, сборка и обслуживание

Одиночные настройки/сохранения и сетевые настройки хранятся раздельно:
`TrainerOS/doom/<content>/solo` и `.../network`. Сетевая игра не переносит
прогресс в одиночный профиль и не получает semantic save capabilities.
Локальный lock препятствует одновременным запускам одного набора в одном режиме.
Существующие пользовательские установки/сохранения других движков не мигрируют
и не перезаписываются.

Пакет: `TrainerOS/emulators/odamex`, запечатанный `manifest.json`:
client/server, штатный служебный `odamex.wad`, Python helpers, зависимости и
существующий `stream_transport`. Игровые IWAD/PWAD в поставку не входят.
Исходники/объекты/контейнеры на Armada собираются на microSD.

- [build.sh](../../packaging/emulators/odamex/build.sh) проверяет pinned source
  и submodules; сервер собирается без UPnP, launcher исключён.
- [bundle.py](../../packaging/emulators/odamex/bundle.py) запечатывает пакет.
- [content.py](../../packaging/emulators/odamex/content.py) отвечает за точные наборы.
- [endpoint.py](../../packaging/emulators/odamex/endpoint.py) связывает штатный UDP
  с существующим защищённым транспортом.
- [check.py](../../packaging/emulators/odamex/check.py) проверяет наборы,
  границы пакетов, разные места, неверных отправителей и отключение.

При обновлении: закрепить upstream revision/submodules, пересобрать пакет,
обновить протокольную идентичность, повторить native подключение и проверки
владения процессами/данными, затем обновлять участников согласованным комплектом.
Rollback — предыдущая shell/helper/package поставка, без удаления `doom/<content>`.
GPL-2.0 и лицензии сторонних библиотек остаются с runtime; оригинальная
интеграция TrainerOS — GPL-3.0-or-later.

## Состояние

Исходники и production-сборка готовы, Flip обновлена поверх актуальной
идентичности аккаунта. Общие 105 runtime, 3 package, 9 content/endpoint и
26 overlay проверок прошли; настоящие native клиенты подключились по 2 и 4.
[Хеши, проверка сохранности и границы доказательства](../evidence/doom-native-20261101/README.md).
Odin не обновляется во время проверки карты владельцем. Прежний Model 3
остаётся установленным на Flip. ROM/IWAD в runtime-поставку не добавлялись.
