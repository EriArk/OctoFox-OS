# Ship Home — управление кораблём и стыковкой: аудит и проект новой схемы

> **Статус: АУДИТ + ЧАСТИЧНО УТВЕРЖДЁННАЯ РАСКЛАДКА.** 22 ноября 2026. Владелец прямо уточнил оси обоих стиков и сочетания L1/L2. **Эти назначения приняты как цель**, все остальные кнопки и сценарии стыковки пока обсуждаются. **Код управления, режимы полёта, тесты и установленные сборки пока не менялись**.
>
> Основной ориентир: **Elite Dangerous + Warframe + Animal Crossing**; физическая пилотажная модель с контроллером, не «пианино» из случайных хорд. См. [полную карту Ship Home и Эгрегора](SHIP_HOME_EGREGORE_DISCUSSION_RU.md), [обзор текущей сцены](../experiences/ship-home/README.md).

## 1. Что фактически назначено сейчас

**Реальные источники:** `experiences/ship-home/scripts/home.gd::_inputs/_unhandled_input/_fly_manual`, `helm_display.gd::event/rows/activate`, `egregore_flight.gd::clearance/interact/tick`, `ship_avionics.gd::hail/plot/jump/boost_drive/...`, `sector_chart.gd`, `project.godot`, `ship_prompts.gd`. В Godot используется **позиционный** ввод, а подписи на экранных подсказках сейчас жёстко адаптированы под Nintendo-раскладку (Joy B = A справа, Joy A = B снизу, Joy Y = X сверху, Joy X = Y слева). Для разных контроллеров нельзя слепо копировать подпись A/B без учёта семейства.

| Сейчас | Фактическое действие | Проблема |
| --- | --- | --- |
| LS | Тангаж/рысканье | Не соответствует принятой новой схеме LS = стрейф + вертикальная тяга |
| RS | Взгляд по кокпиту | Должен перейти на тангаж + крен, а с L1 горизонтальное отклонение становится рысканьем |
| LT / RT | Тормоз/двухэтапный реверс / тяга вперёд | Не соответствует решению L2 = тяга вперёд, L1 + L2 = тяга назад; прочие триггеры ещё распределить |
| LB / RB | Крен; в каталогах листание | Крен переводится на правый стик; L1 должен стать модификатором, R1 остаётся не назначен новым решением |
| D-pad | Горизонтальная/вертикальная тяга; при Y + D-pad выбор 4 приборных панелей | Перегрузка и отсутствие быстрого доступа к приборным панелям |
| A справа (Godot `JOY_BUTTON_B`) | Взлёт / посадка / стрельба при выпущенных орудиях | Одна кнопка совершает несвязанные критические действия |
| B снизу (Godot `JOY_BUTTON_A`) | Выйти из кресла, включая полёт/автопосадку | Возможны случайные выходы; но **возможность ходить по кораблю во время полёта надо сохранить** |
| X сверху (Godot `JOY_BUTTON_Y`, action `decorate`) | Торможение во время полёта | Дублирует LT, название action не по смыслу |
| Y слева (Godot `JOY_BUTTON_X`) | Коротко — цель по курсу; удерживать + D-pad — панели; с L3 — режим прицела; с A — противоракетная защита | Сложно обнаружить; панели требуют комбинаций |
| L3 | Смена оружия | Ускорение (boost) прямой кнопки не имеет |
| R3 | Приближение к радару / Scope | Быстрой стабилизации/precision mode нет |
| Start | Меню паузы | Оставить |
| View/Select | Не используется как штатная прямая команда пилотирования | Резерв для оружия/режимов |
| Панели/карта | Устройства, нацеливание, lock, hail, request pad, cruise, boost, shift jump, engine service, power и т.д. | Формально доступны через меню, но крайне неудобны для частых действий в полёте |

**Дополнительный UX-дефект:** `_action_hints()` показывает `A · Land` только при уже выполненных условиях. Если разрешение отсутствует, прямой подсказки `A · Request clearance` нет — игрок должен догадаться открыть Contacts → выбрать станцию → Contact → Request pad 01.

**Ещё один технический риск:** когда открывается панель, `home.gd::_physics_process` передаёт нулевые управляющие оси в `flight.tick(... brake=false)`, но сохранившийся `throttle` и инерция корабля не обязательно обнуляются. Игрок читает меню разрешения на стоянку, а корабль может продолжать движение. Нужно независимое от интерфейса поведение полётного ассистента.

## 2. Принятая основа управления: отдельно поступательное движение и ориентация [РЕШЕНО ВЛАДЕЛЬЦЕМ]

**Тип управления: gamepad-HOSAS (Hands On Stick And Stick)** — два аналоговых стика разделяют три оси поступательного движения и три оси ориентации. Это именно адаптация идеи HOSAS под компактную портативку, а не классический HOTAS или обычная схема «левый стик — поворот, правый — камера». Ведущая идея: левый стик отвечает за локальную трансляцию, правый — за вращение; L1 заменяет ось крена на рысканье и разворачивает направление тяги L2. Единая логика применяется и в космосе, и при маневрировании возле посадочной площадки.

**Последнее явное решение, 22 ноября 2026:** *«Левый вверх/вниз/стрейф, правый нос вверх/вниз/ролл (поворот с модификатором). L1 клавиша модификатор. L2 тяга вперед (назад с модификатором)».*

Ниже назначение по **физическим органам управления** (стики, плечевые кнопки), не по потенциально различающимся буквенным подписям A/B/X/Y разных семейств контроллеров.

| Орган управления | Без L1 | С зажатым L1 |
| --- | --- | --- |
| **Левый стик ←/→** | Боковое смещение корабля (strafe) влево/вправо | **Пока не уточнено** |
| **Левый стик ↑/↓** | Вертикальная тяга — подъём/снижение | **Пока не уточнено** |
| **Правый стик ↑/↓** | Тангаж — нос вверх/вниз (pitch) | **Пока не уточнено** |
| **Правый стик ←/→** | Крен влево/вправо (roll) | Поворот носа влево/вправо (yaw) **вместо крена** |
| **L2** | Поступательная тяга **вперёд** | Поступательная тяга **назад** |
| **L1** | Удерживаемый модификатор | — |

Это **не** прежняя предложенная схема LS=тангаж/рысканье, RS=стрейф, RT=тяга, LB/RB=крен. **Она отклонена и не должна использоваться как цель реализации.**

### Оставшиеся органы управления [ОТКРЫТО]

**R1, R2, L3, R3, крестовина, A/B/X/Y, View/Select, Start**, а также торможение, boost, cruise, выбор цели, HUD, свободный обзор, стрельба, выпуск оружия, вызов диспетчера, стыковка, автопилот и выход из кресла — пока **не назначены новым решением**. Старые действия из раздела 1 — только описание действующего кода. Не навязывать прежний кандидат `Y+RS`, `B short` или `D-pad panels` без отдельного согласования.

**Техническое следствие:** при нажатом L1 правый стик по оси X должен подавать **yaw, а не roll**; при нажатом L1 аналоговый L2 меняет **направление тяги** с вперёд на назад. Нужно спроектировать обработку отпускания L1 при ненулевых отклонениях стика/триггера без резкого неожиданного рывка и проверить реальное направление осей на Odin 2/Flip 2.

**Контексты меню и карты:** в открытом интерфейсе стики могут служить навигации/вращению карты и не обязаны воздействовать на корабль. Эти правила тоже ещё требуют согласования. Новые игровые функции не должны предполагать лишние комбинации L1, пока роль модификатора формально не распределена.

## 3. Проблемы текущей стыковки

`egregore_flight.gd::clearance()`:

| Условие | Остров | Станция |
| --- | --- | --- |
| Радиус по горизонтали | До **80 м** | **8 м** |
| Относительная высота | От −2 до +120 м | Приблизительно от −0,3 до +9 м |
| Скорость | В существующем пути island assist прямого лимита нет | Менее **2,5 м/с** |
| Ориентация | При посадке автовыравнивание | Почти горизонтальная (dot up > 0,94) |
| Запрос разрешения | Не нужен | Обязателен: Contacts → станция → Hail в пределах **850 м** |
| Завершающий манёвр | Автоматический с облетом рельефа | Точное ручное наведение, затем автоманёвр |

Для станции необходимо одновременно выбрать landing site (а не случайный корабль/контакт), запросить clearance, вручную выровнять и замедлиться. `home.gd` на A, если условия не выполнены, в основном **показывает текст отказа**, а не запускает подходящий следующий шаг.

## 4. Стыковка — незаконченный проект UX [ОБСУЖДАЕМ, НЕ УТВЕРЖДЕНО]

**Общее направление на рассмотрение:** выбор станции/острова → запрос разрешения в пределах 850 м для станции → точный подлёт → финальное выравнивание/посадка, возможно с помощью assist. Всё это должно оставаться управляемым на геймпаде без длинного пути по меню.

- Отдельно решить **чем** вызывается диспетчер, **какой кнопкой** разрешение принимается, **какой кнопкой** выполняется посадка и нужен ли ручной или автоматический финальный заход.
- В существующем коде острова уже поддерживают assist-посадку из более широкого радиуса, станции требуют существенно более точного ручного сближения. Возможная унификация **не утверждена**.
- После разрешения на станцию показывать понятные данные: дистанция до pad, высота, скорость, состояние разрешения, доступное действие и причина отказа.
- Пропажу тяги/непреднамеренную активацию при открытии карты, смене контекста, выходе из кресла и переключении L1 проверять отдельно.
- Служебная заправка/ремонт не меняют денежную политику из-за изменения управления.

**Запрет на самовольное назначение:** прежний набросок про `A · Request/Dock`, `B short · Precision`, `B hold · Stand`, `LT · Brake`, 50–80 м assisted station landing и «ручная стыковка только опционально» — **предложения автора аудита, которые владелец пока не утверждал**. Не переносить их в код как требование.

## 5. Системная архитектура ввода

- **Один владелец контекста**: `Walking`, `PilotFlight`, `PilotArmed`, `PilotDockAssist`, `PilotPanels`, `PilotChart`, `PilotLanding`, `Pause`. Приоритеты и переходы заданы явно; не пытаться трактовать одинаковый InputEvent сразу в `helm_display._input` и `home._unhandled_input` как два независимых действия.
- Использовать semantic actions, их биндинги в одном месте, не мешать `decorate/confirm_place/rotate_left` с пилотированием. При повторном создании Ship Home не дублировать InputMap events.
- Учитывать Nintendo/Xbox/PlayStation/Steam input family для физической раскладки и HUD glyphs. `JOY_BUTTON_B` не означает буквальную кнопку «B» на Odin. Проверять кнопки по позиции/профилю, а не только надписи.
- Реализовать L1 как модификатор с явным приоритетом над стандартными стиковыми/триггерными действиями. **L1+правый X = yaw вместо roll; L1+L2 = реверс вместо тяги вперёд**. При отпускании L1, переключении режима, входе в панели и потере фокуса не допускать двойной команды/неожиданного рывка. Если позже утверждаются короткие/длинные нажатия, различать их без случайных действий.
- Вся точная тяга/flight assist остаётся физическим движением `flight.tick`, посадка — управляемой траекторией/коллизиями, а не мгновенным reset.
- При входе в панели и при вставании из кресла определять предсказуемое удержание позиции/постепенное торможение. Не возобновлять неожиданно старый throttle после закрытия меню.
- При потере ввода или отключении геймпада не удерживать навсегда ускорение или fire.
- Keyboard/mouse/touch сохраняют функциональность; подсказки переключаются по последнему устройству без путаницы.
- Поддержать настраиваемые раскладки позднее поверх семантического слоя; не копировать UI-модуль из оболочки без теста целевых устройств.

## 6. Минимальная проверка на настоящем железе

- Реально нажать каждую кнопку на **Odin 2 и Flip 2**, сверить семейство A/B/X/Y, направления стиков/триггеров, перехват системных клавиш, задержку B hold и R3.
- Проверить направление **обоих стиков**, LS strafe/lift, RS pitch/roll и **L1+RS X = yaw**, включая диагональное отклонение и возврат стика в центр.
- Проверить **L2 вперёд** и **L1+L2 назад**, переход L1 при частично зажатом L2, отпускание и отсутствие скачка тяги. Остальные команды тестировать после утверждения кнопок.
- На станции: выбрать из атласа → подлететь на 850 м → запросить разрешение с утверждённого контроллера → сблизиться и выполнить стыковку без мыши. Порог и кнопки будут определены отдельно.
- Проверить 6 станций и все 10 островов, collision/trajectory, снятие разрешения в нужный момент, сохранение точного причала, отсутствие повторного сброса при timeout.
- Проверить после назначения остальных кнопок: бой (hardpoints/lock/fire/weapon group/point defence), посадку, панели, свободный взгляд, отсутствие пересечения с L1 и 6DoF-управлением.
- Проверить полёт с открытой картой/навигацией, переход из меню в cockpit, геймпад disconnect/reconnect, touch/mouse и фокус окна.
- Обновить тесты `experiences/ship-home/tests/flight.gd`, `avionics.gd`, `pilot_checks.gd`, `boarding.gd`, `tests/helm...` при новом дизайне; не принимать простой unit-test за физическую приёмку.

## 7. Статус договорённостей

- **[ЗАПРОС ВЛАДЕЛЬЦА, 2026-11-22]** Полностью пересмотреть назначение кнопок и процесс стыковки: есть отсутствующие, неверно назначенные и неудобные действия.
- **[РЕАЛИЗОВАНО РАНЕЕ]** Базовый полёт, D-pad-thrusters, выдвижные панели, 3D карта, рукопашные манёвры, островная Assisted Land, строгая станционная посадка, подача запроса через меню.
- **[РЕШЕНО ВЛАДЕЛЬЦЕМ]** LS X = strafe, LS Y = вертикальная тяга; RS Y = pitch, RS X = roll, с L1 RS X = yaw; L1 — модификатор; L2 = тяга вперёд, L1+L2 = тяга назад. Старый кандидат с LS=поворотом/RS=стрейфом отклонён.
- **[ОБСУЖДАЕМ, НЕ УТВЕРЖДЕНО]** Кнопки остальных функций, интерфейс разрешения на стыковку и форма финального посадочного ассистента.
- **[ОТКРЫТО]** Поведение прочих осей с L1, R1/R2/L3/R3, D-pad, A/B/X/Y/Select, обзор, торможение, boost/cruise, стрельба/lock, точные процедуры и пороги docking, walk while airborne.
- **[НЕ СДЕЛАНО ЭТИМ ДОКУМЕНТОМ]** Код, переразметка InputMap, приёмка и установка на портативки.
