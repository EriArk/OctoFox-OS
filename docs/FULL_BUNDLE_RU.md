# Автономный комплект TrainerOS

Владелец попросил собрать оболочку, обычные и модифицированные эмуляторы,
зависимости и важные параметры мультиплеера в один комплект поверх Armada.
Armada остаётся отдельной базовой ОС. Обновление оболочки не должно требовать
повторной загрузки всех эмуляторов.

## Состав кандидата от 3 ноября 2026

Собраны точные рабочие артефакты с закреплёнными версиями:

- 16 отдельных native-комплектов: Azahar, Dolphin NetPlay/LAN, Flycast
  NetPlay/Online/LAN, melonDS, RMG, PS2 LAN, PCSX-ReARMed CBIN, NeoCD,
  NGPC, Odamex, Supermodel, Vita3K, xemu.
- 76 ядер RetroArch и 72 информационных файла; среди ядер — изменённые
  варианты для link/netplay. Обычные ядра и сетевые варианты не подменяют друг друга.
- AppImage ARMSX2, Azahar Enhanced, Cemu, melonDS, DuckStation, Eden,
  RPCS3; xemu AppImage находится в отдельном native-комплекте.
- Flatpak RetroArch, **PPSSPP traineros-relay**, Dolphin, Flycast и их
  закреплённые платформенные/графические библиотеки. Обычный PPSSPP stable
  не заменяет сетевую сборку.
- PSP content/network helpers, передача связанных сохранений, Remote Play,
  capture helper и 38 закреплённых Python wheels для голоса/сетевых помощников.
- Исходники ранее собранной оболочки, доступные upstream notices/patches,
  рецепты сборки и отдельная [опись параметров мультиплеера](../packaging/emulators/fullbundle-settings.json).

В архив не копируются ROM, пользовательские BIOS, сохранения, аккаунты,
глобальные конфиги и старые резервные копии с портативок. NGPC содержит
собственную HLE-реализацию своего проекта. Требования к пользовательским
firmware остаются в манифестах; отсутствие этих файлов не превращается
в фиктивную готовность игры. Пути PS2 к домашнему каталогу превращены в
шаблон `${HOME}`, который должен заполняться установщиком для нового пользователя.

## Настройки и совместимость

Источник настроек — существующие генераторы изолированной игровой сессии,
а не скопированный профиль разработчика. Сохраняются защита сохранений,
согласованные контроллерные порты, отключение конфликтующих rewind/run-ahead,
автозагрузки savestate и паузы от потери фокуса. PPSSPP сохраняет индивидуальный
MAC устройства; сервер/роль формируются для принятого приглашения. Специальный
ForceLagSync2 остаётся ограничен точным профилем Lumines.

Состав фиксируется [рецептом ARM64](../packaging/emulators/fullbundle-arm64.json):
исходная ревизия, protocol/settings и контрольные суммы обязательных файлов.
Python в закреплённой Armada `20261102.d4f6880` совпадает с ожидаемым сетевыми
сборками: `ef59e677…`. Будущее обновление ОС требует проверки совместимости;
ограничения admission не ослаблены ради упаковки.

PS2 shared-console/libretro и melonDS WFC, отсутствующие в установленном наборе,
не объявляются доставленными. Их исходники и прежние ограничения сохранены.
Новые игры, разные внешние сети, физический ввод/голос этой сборкой не проверены.

## Инструменты и установка

`collect_runtimes.py` принимает явный allowlist и отказывается собирать изменённый
runtime, внешнюю ссылку либо непредусмотренный путь. `runtime_payload.py` проверяет
файлы до упаковки и повторно в готовом компоненте. `fullbundle.py` собирает
отдельные компоненты в один операторский архив с полной описью SHA-256 и проверяет
весь архив. Он **не выдаёт разрешение на публичное распространение**.

Setup умеет устанавливать Software из локальной подписанной пары
`release.json` / `traineros.tar.gz`: `--offline <каталог>` либо каталог `offline`
рядом с bootstrap. Используется доверенный ключ установки, проверяются подпись,
совместимость данных и хеш архива. Скрытого сетевого fallback нет. Откат версии
остаётся отдельным действием Recovery. Клиентский OTA и обновление Armada
сохраняют прежнее разделение.

В общий список устанавливаемых помощников добавлены `fluxer-voice.py`,
`voice_presence.py`, `fluxer_streams.py`, `game_capture.py`. Сам по себе перенос
этих скриптов не устанавливает Python-окружение или native capture.

## Проверки

88 Python-проверок прошли на ARM64 Linux: сборка и границы медиапакета,
Release/Channel/Installation, состав помощников. Реальный пакет Software прошёл
prepare/install/audit/repeat/uninstall без сети в закреплённой Armada с отдельным
validation-ключом; хеши тестовых личных данных после удаления совпали.
38 wheels установлены там же без сети, `pip check` и импорты LiveKit/Wormhole/
crypto/network-модулей прошли. Это не проверка речи или звонка.

Все 12 Flatpak refs проверены импортом без сети и совпадением
commit/binary identities. Контейнер запрещает вложенные namespace bubblewrap;
его предупреждения ограничивают этот результат импортом пакетов. Запуск
приложений и полная системная приёмка не заявляются.

[Архив, контрольные суммы и evidence](evidence/2026-11-03-full-bundle/README.md).
Итоговый архив занимает 3,10 GB. Для GitHub подготовлена разбивка на две части
с отдельными и общим SHA-256: официальный лимит — меньше 2 GiB на asset
([GitHub Docs](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases#storage-and-bandwidth-quotas)).
Это формат доставки; загрузчик частей в единый Setup остаётся частью следующего цикла.

Первый архив `TrainerOS-Full-CANDIDATE.tar` остаётся комплектом компонентов.
Новый `offline_setup.py` оборачивает его и подписанный Software в отдельный
`TrainerOS-Full-Setup-CANDIDATE.tar`: одна папка, один вход `Install TrainerOS.sh`.
Это кандидат для проверки, не опубликованный/лицензионно очищенный выпуск.

## Общий установщик и восстановление

- `runtime-set.json` подписан тем же доверенным ключом, что и Software, и привязан
  к его source revision. Хеши неподписанного `fullbundle.json` не разрешают установку.
  Проверяются архив, каждый компонент, пути, объём и точный Python базовой Armada.
- Файлы native/AppImage/RetroArch попадают только в предусмотренные каталоги.
  `${HOME}` в манифестах заменяется домашним каталогом текущего пользователя.
  Python-окружения создаются заново из закреплённых wheels без сети по постоянным
  путям поколения. Старое окружение можно использовать лишь при совпадении Python,
  списка зависимостей и файлов пакетов; другое окружение сохраняется и требует
  отдельной миграции. Личные конфиги, firmware, ROM и сохранения не являются payload.
- Flatpak устанавливается в пользовательский scope, включая `traineros-relay`
  PPSSPP; сохраняются исходные commits и выбранные ветки. Не используются удаление
  app data или принудительное удаление зависимостей. Изменение managed Flatpak
  внешним обновлением останавливает перезапись и требует разбора.
- `runtime_transaction.py` хранит исходные файлы/режимы и журнал before/after.
  Явная миграция заменяет код с резервной копией; чужие изменения во время операции
  не затираются. Общий журнал охватывает файлы, Flatpak, системные helpers и Software.
  Продолжение и отмена работают в том числе после частичного commit внутренних
  журналов. Пока общий журнал открыт, managed launcher не запускает оболочку.
  Отдельный маркер завершения Setup сохраняется до регистрации сессии: отмена
  системной авторизации не превращается в ложное «установлено». Повторный вход
  завершает этот шаг без новой загрузки; удаление также можно продолжить.
- Привилегированный шаг ограничен capture/Remote Play в собственном каталоге,
  имеет отдельный root-owned журнал и обычное подтверждение администратора.
  Загрузочная сессия по умолчанию и ОС не меняются. Регистрация сессии выполняется
  существующим additive installer; её проверка не подменяется тестом runtime journal.
- Setup умеет обновлять полный набор и возвращать предыдущее поколение вместе
  с сохранённой совместимой версией Software. Удаление возвращает исходный код,
  сохраняя app data. Подготовленные поколения и резервные blobs остаются в managed
  хранилище для восстановления; это не обещание полного освобождения места.
  Обновление самого bootstrap по-прежнему требует совпадающего recovery installer.
- На чистом профиле RetroArch использует установленный linked-save helper без
  записанных вручную путей портативки. Явные переопределения имеют приоритет;
  exact-content admission и защищённый жизненный цикл сохранений сохранены.

Проверки сбоя между этапами, подписи, изменённого кода, отмены авторизации и
возврата оригинальных файлов выполняются отдельно от реального многогигабайтного
набора. Реальная проверка в контейнере не доказывает запуск Flatpak, диалог pkexec
или переход Desktop/TrainerOS на чистой портативке.

## Оставшийся обязательный цикл

1. Завершить проверку реального набора: подготовка, прерывание/продолжение,
   повтор, обновление, откат и удаление с сохранением контрольных личных файлов.
2. Проверить установку/возврат в исходную ОС в чистой системе, затем обновление
   существующей установки. Проверка внутри контейнера не заменяет этот цикл.
3. Завершить corresponding-source/licence inventory для **всех** распространяемых
   бинарников и упаковку аватара; затем production-подпись, GitHub assets/feed
   и образ из того же набора. Отдельные source snapshots не закрывают весь пункт.

Публичный выпуск, новая прошивка/загрузочный выбор и установка комплекта на
личные профили портативок этим проходом не выполнялись.
