## Проход на Flip

Перед установкой исходная сессия была Armada/Steam, без установленного
TrainerOS launcher. Сохранялись неполные остатки старого beta/preview Setup.
Неактивный root без receipt/journal/owned files отложен отдельно; его trust и
bootstrap не переименованы в Alpha. Все сохранённые личные profile/runtime homes
и последний pre-clean recovery root оставлены.

Очищены только неактивные распакованные runtime generations двух старых
удалённых установок, staging прерванной установки и generated object/resource
каталоги старой сборки. Проверены отсутствие active/previous receipts, pending
journals и live references. Runtime manifests и code recovery blobs сохранены;
игры, BIOS, saves и runtime-home не входят в удаление.

Новый Setup скачан через HTTPS на microSD, размер и SHA-256 проверены, архив
распакован. Обычный `Install TrainerOS.sh` запущен **один раз** из Desktop при
отсутствующих program/profile roots. Через реальные kdialog окна выбран Alpha
и подтверждена установка. [Подтверждение](setup-confirm.png),
[проверка комплекта](setup-progress.png). Ввод передан виртуальной USB-клавиатурой
через uinput; это удалённая проверка UI, не доказательство физических кнопок.

Последний полученный этап — подготовка `org.kde.Platform/aarch64/6.10`.
Затем Flip продолжал отвечать на ping, но новые SSH-команды перестали
возвращать результат. Это не доказательство завершения или падения Setup;
принудительно прерывать работающий установщик не стали. Владелец подтвердил
живое окно и растущий таймер; на фото — подготовка KDE 6.10, 9m17s. Это
подтверждает работу окна, но не продвижение дочернего процесса упаковки.
Финал Setup, новый wizard, восстановленные аккаунты,
импорт/запуск, Apps/Quick Apps и реальный OTA пока не засчитаны.

## Обновление существующего Odin

По отдельному указанию владельца Flip оставлен доустанавливать, Odin обновлён
на месте, без чистой установки эмуляторов или создания managed Software receipt.
Подписанный Software 24 проверен штатным `releases.prepare`; активный ELF сверён
через `/proc/<pid>/exe` с `30e1dd68…`. Обновлены 89 файлов приложения и ресурсов,
31 session/integration helper проверен по исходникам. `install.py --user armada`
завершился успешно, standalone TrainerOS запущен штатным session control.

Сохранены прежние бинарник/ресурсы, снимок SQLite и настройки, а также root helpers.
Для прежнего native prefix оставлены две рабочие частные библиотеки Files:
их `$ORIGIN`-настройка отличается от нового managed launcher с LD_LIBRARY_PATH.
Проверка `ldd -r` не нашла отсутствующих библиотек или символов. Это особенности
существующей установки, не изменение подписанного пакета.

База после запуска: quick_check ok, 542 adventures, число строк во всех прежних
таблицах совпадает. Сохранились профиль, его 3D-аватар, выбранный Home Companion
и библиотека. [Обезличенный readback](odin-legacy-update.json).

На настоящем экране удалёнными кликами/клавишами проверены Home, профиль с круглой
кнопкой Wardrobe, Chats с боковой панелью, Apps/Crates, Browser с загрузкой Wikipedia,
Files с чтением прежнего каталога, Start, [Settings/System](odin-system.png). Из Apps запущен Ark
до его настоящего окна, закрыт обычным Ctrl+Q; подтверждён возврат фокуса
в оболочку и переход на Home. Alt+F4 сам по себе окно в этой сессии не закрыл. Проверка журнала этого
запуска не обнаружила ReferenceError/TypeError/ошибок загрузки QML. Скриншоты с
личным профилем и библиотекой сохранены только в private evidence.

Полный свежий wizard, импорт BIOS/игр, физический джой, цикл Home/minimize/resume
нативного приложения и Software OTA на устройствах этим проходом ещё не доказаны.
На Odin System корректно показывает development build · alpha: это ручное обновление
существующей установки, не имитация managed OTA. Игровой мультиплеер не проверялся.

На Odin удалён только собственный распакованный staging новой версии после
проверки работающего ELF; rollback files, снимок базы и настройки оставлены.
