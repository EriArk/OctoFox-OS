# Home: общий слот и граница адаптера — 2 ноября 2026

Владелец потребовал отдать освобождённую от inbox область пользовательскому
виджету и отверг её уменьшение при активном адаптере. Причина находилась в общей
компоновке `HomeDashboard.qml`: она выносила достижения в левую колонку.

Теперь левая колонка одинакова для всех игр. Адаптер сохраняет высоту своего
представления в карточке справа; достижения выбранной игры находятся там же.
При логическом viewport 960×540 свободно 269×211: стандартный блок Start 4×4
занимает 232×208. Слот использует ширину колонки и высоту 208. При 800×450
остаётся 216×121, используется компактное представление. Подробный
[расчёт и управление](../../CONTROLS78_HOME_START.md#home-widget-area).

`HomeDashboardController` сохраняет Downloads/Storage/Clock/Battery либо пустой
слот для текущего профиля через QSettings. Выбор независим от игры и Start.
`HomeWidgetSlot` использует существующий `ControlWidget`; Downloads открывает
общую очередь, остальные действия используют Settings/Power. Нет нового
backend, постоянного сканирования или исполнения внешнего QML.

По дополнительному уточнению владельца колокольчик сдвинут левее. Его область
44×44 центрирована в панели высотой 63; верхний, правый и нижний отступы равны
9,5 логического пикселя. Область имени и её touch-граница учитывают новое положение.
Правая граница поповера по-прежнему совпадает с левым краем карточки игры.

Во время проверки на Flip обнаружено, что Storage до открытия Start не имел
снимка DeviceService. Исправлено разовым асинхронным запросом при появлении
выбранного Storage на Home. Смена фокуса не запускает новый запрос; постоянный
опрос Home не добавлен. Скрытый/снятый виджет не запрашивает данные.
Запрос поставлен через `Qt.callLater`, чтобы сигнал DeviceController не вызывал
повторное вычисление `storageVisible` внутри его же обработчика. Последняя сборка
на обоих устройствах работает без ошибок QML в журнале текущего процесса.

Проверки разделены:

- Native Qt: 8 passed в целевых ExperienceTests, включая сохранение между
  профилями/пересозданием, независимость от адаптера/Start, неверный ID, Back,
  Quick Apps, открытие Downloads без запуска игры и запрос Storage.
- ARM Linux: core — 8 passed; целевые Home-сценарии — 7 passed до production build.
  Итоговые числа и исполняемый SHA записаны в [checks.json](checks.json).
- Home UI и повторный запуск проверяют общий слот в адаптерной и generic
  компоновках, отрисовку Pokémon badge/party fixtures, выбор, 960×540/800×450,
  возвращение маршрутов и отсутствие QML warnings. Плотность offscreen-теста
  задаётся явно; прежнее предположение, что размер окна равен логическому
  viewport при любом Screen, было неверным. Личные настройки плотности
  восстанавливаются после теста.
- На устройствах отдельно проверены UI-выбор и установленный процесс;
  синтетический SDL/X11 ввод не объявляется физической приёмкой контроллеров.

Итоговая production-сборка установлена на Flip и Odin. Проверено совпадение SHA
запущенных процессов; настройки, игровые записи и avatar pack сохранились.
На Flip Storage пережил перезапуск и сразу показал реальные объёмы; Downloads
открывал существующую очередь. На Odin сохранился Clock. На обоих проверены
выбор виджета и поповер колокольчика; после проверки оставлен пустой слот,
чтобы владелец выбрал виджет сам. Odin оставлен с громкостью 0%.

Основная сборка содержит общий main `785dd836`, включая опубликованную работу
других чатов. Отдельный native ARM64 core DS WFC в этом проходе не поставлялся;
наличие его shell binding не доказывает доступный WFC runtime или сетевую игру.
Системные helpers, avatar pack, профили, сохранения и игровые записи сохраняются.

Внешние SDK-виджеты в этом слоте, физическая приёмка и ранее отложенный ручной
Settings/library-scan/restart не закрываются этим результатом.
