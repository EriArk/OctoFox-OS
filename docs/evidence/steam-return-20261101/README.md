# Возврат из Steam и проверка обеих портативок — 1 ноября 2026

Продолжение [исправления перехода](../steam-session-20261029/README.md) и
[завершения оболочки](../shell-teardown-20261029/README.md). Граница S15/R117.
Проверяемый путь: **TrainerOS Start → Switch → Steam Gaming Mode → меню Steam →
Выключение → Перейти к рабочему столу → Return to TrainerOS в приложениях Plasma**.
Это маршрут через рабочий стол, не новый пункт непосредственно в меню Steam.

## Изменение

Ярлык возврата включён в установку сессии; прежняя отдельная ручная команда больше
не нужна. Файл с английским/русским именем находится рядом с root-owned helpers.
Пользовательский helper создаёт только ссылку в меню приложений, работает без root
и сохраняет существующие обычные файлы и произвольные ссылки. При управляемом
удалении удаляется только точная ссылка на наш файл; проверка ownership выполняется
до этого шага. `TryExec` скрывает новую запись при отсутствии session helper.
Ранее вручную установленные ярлыки сохраняют своё содержимое.

Armada на проверенных устройствах держит `/usr/local` read-only; итоговое решение
не меняет `/usr`, скрипты Steam, предпочтение рабочего стола SteamOS Manager или
предустановленные Plasma entrypoints. Обновлены только файлы возврата. Бинарник
TrainerOS остался прежним, SHA-256 на обоих устройствах:
`b667747b3adcd0833aac1b7ca6e5e25324668f912e53dff38852be760333cabf`.

## Фактическая проверка

- **Odin:** переход из Start с подтверждением; Steam отрисовал меню, сохранил вход
  и реагировал на выбор пунктов. Штатный переход Steam в Plasma Mobile выполнен.
  В поиске приложений выбран именно **Return to TrainerOS**, а не обычный запуск
  приложения TrainerOS внутри рабочего стола. Получена новая выделенная сессия,
  после загрузки показан прежний профиль и открывается Start.
- **Flip:** тот же переход из Start. Steam автоматически обновил свой клиент,
  затем показал домашний экран с библиотекой и рабочее меню с сохранённым входом.
  Через пункт рабочего стола открыт Plasma Mobile, затем из поиска запущен
  Return to TrainerOS. Вернувшаяся оболочка показывает прежний профиль и Start.
- На обоих устройствах итоговый `traineros-session.service` active, Steam unit
  inactive; процессов `plasmashell` после возврата нет. SQLite `quick_check` — `ok`.
  Предпочтение Desktop осталось `armada-plasma-mobile.desktop`.
- На обоих прошли **12/12 SessionSupervisorTests**: реальные Linux lifecycle
  проверки плюс создание/повторная установка/удаление своей ссылки и сохранение
  старых/изменённых ярлыков. На Windows прошли **4 HostAndOwnershipTests**;
  это отдельная локальная проверка, не доказательство устройства.
- Оба новых файла доставлены на обе портативки; `desktop-file-validate` прошёл.
  Полная повторная установка/удаление продукта на живых профилях не проводилась.
- Управление проверялось удалёнными событиями X11/uinput. Это проверка видимого
  интерфейса на реальных устройствах, а не физическое нажатие владельцем.
  Приватные кадры и диагностические файлы находятся в игнорируемом
  `build/steam-return01/` и `build/support29/`, не публикуются.

## Оставшиеся дефекты и границы

Последующий [разбор и исправление](../session-polish-20261101/README.md) устраняет
два описанных ниже дефекта на проверенных устройствах. Этот раздел сохраняет
результат первоначальной проверки, а не текущий статус исправления.

- На **Flip** при уходе из Plasma зарегистрирован **SIGSEGV в plasmashell**.
  Он не остановил переход: новая сессия TrainerOS отрисовалась и отвечает.
  Причина падения Plasma не установлена и не объявляется исправленной этим
  изменением. Системный coredump усечён; необходим отдельный разбор завершения
  рабочего стола. На Odin такого события в этой проверке не обнаружено.
- После рабочего стола яркость на обеих портативках стала около 33–34% вместо
  исходных 75%. Исходные 75% восстановлены через Start; перенос яркости между
  окружениями требует отдельного исправления. Odin оставлен с громкостью 0%.
- Физические кнопки, игры Steam, смена Steam-аккаунта и сон не проверялись.
  Интеграция Steam library внутри TrainerOS по #69/R117 остаётся открытой.
  Полный R117 не закрыт. Следующий ограниченный шаг — завершение Plasma и
  сохранение яркости при смене окружения, затем интеграция библиотеки.
