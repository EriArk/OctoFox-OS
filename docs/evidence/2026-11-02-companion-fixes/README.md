## Реализация

- `AvatarView3D` использует штатный Qt Quick 3D `Skin`, настоящий риг и inverse
  bind matrices. CPU обновляет кости, выражения и sockets. Изменение одной позы
  больше не пересчитывает/загружает все вершины; изменившиеся morphs обновляют
  только затронутые части. Исходная геометрия, одежда, UV и риг не менялись.
- Полный Loader Companion выгружается вне активного Home, при Start, drawers,
  клавиатуре и потере активности приложения. Он возвращается одним экземпляром.
  Таймеры представления останавливаются, незавершённый GLB parse отменяется на
  следующем accessor. Игровое время/очередь достижений остаются в общих сервисах;
  выгрузка не вызывает Rest и не добавляет энергию.
- Home-contribution по умолчанию не получает Start capability; `widget.put`
  возвращает `home_only_app`, а обновление inventory удаляет прежние вклады.
  Отдельные Start-приложения продолжают работать. Явный manifest opt-in описан
  в [SDK](../../../sdk/HOME_WIDGETS.md); у Companion его нет.
- Одна статическая маска обрезает фон, 3D, индикаторы, меню и рамку. Размер
  offscreen-текстуры учитывает экранный масштаб: текст не растягивается из
  маленького буфера. Размер слота и области нажатий сохранены.

Использованы публичные API Qt: [Skin](https://doc.qt.io/qt-6/qml-qtquick3d-skin.html),
[custom geometry skinning](https://doc.qt.io/qt-6/qtquick3d-skinning-example.html),
[MultiEffect](https://doc.qt.io/qt-6/qml-qtquick-effects-multieffect.html).

## Проверки на сервере

Linux x86_64, Qt 6.11.2, Release, C++20. Оболочка собрана с тестовыми сценариями;
контейнер без Qt WebEngine — это проверочная сборка, не ARM-пакет для доставки.

| Набор | Passed | Failed | Skipped |
|---|---:|---:|---:|
| AvatarScene | 6 | 0 | 0 |
| Experience | 33 | 0 | 0 |
| PlatformHost | 17 | 0 | 1 |
| HomeCompanion | 8 | 0 | 0 |

64 passed, один прежний skip внешнего Godot consumer. Новый тест сравнивает
выборки вершин одетого аватара с CPU reference для нейтральной позы, laughing,
Sit, head offset и Arms_Up с допуском 0,0001. При изменении только позы счётчик
загрузок геометрии не растёт; очистка source освобождает owned geometry.
SDK-тест проверяет отказ, снятие прежнего Start-вклада, отсутствие capability
при новом подключении и сохранение работающего Session Timer; manifest opt-in
проверен отдельно. Install/update/remove/reinstall сохраняют выбор/потребности.

Диагностический CPU benchmark 24 изменений позы одетого аватара:
538,515 мс retained CPU reference против 4,857 мс подготовки GPU palette.
Это время CPU-вычисления в одном серверном тесте, **не** FPS, GPU-время,
ускорение всей оболочки или прогноз нагрузки портативки. Предыдущие Flip
112%/36,2% остаются историческим замером старой сборки.

Полный HomeSmoke: `qmlWarnings=0`, проверены связанные выбор/действия/удаление/
возврат и уничтожение внешнего Loader при `presentationActive=false`.
Этот сценарий использует mock без 3D. Отдельный настоящий 3D preview с racing
костюмом проверяет Feed/Rest, меню, поздравление, normal/compact, light/dark,
четыре угла по пикселям и три цикла уничтожения/возврата. `QPointer` подтверждает
уничтожение AvatarScene и принадлежащей геометрии; после возврата одна сцена,
care активен, предупреждений нет. Это владение Qt-объектами, не измерение RSS
или аппаратных GPU allocations. Кадры анимации просмотрены визуально.

## Оставшаяся приёмка и следующий шаг

После разрешения владельца совместить с актуальной работой другого чата,
собрать ARM Release и безопасно обновить Flip/Odin. На Flip без параллельной
сборки сравнить одинаковые CPU/RSS выборки Companion/Clock/другая страница/Start/
возврат, доступные GPU-показатели и несколько настоящих переходов, включая игру.
Проверить смену профиля, Feed/Rest, удаление/переустановку с сохранением данных.
Odin не использовать для сборок или дискового стресс-теста; сон/lid не проверять.
Физические кнопки, длительная работа, батарея и реальные новые игровые достижения
остаются отдельной приёмкой. Issues не закрываются по серверному preview.
