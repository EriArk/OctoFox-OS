## Odin: обновление прежней установки

[Обновление приложения](odin-delivery.json) выполнено без сброса runtime и профиля.
3913 личных файлов побайтово сохранены при замене; проверенная копия прежних файлов

Games → Emulators, выбор PS3 и кнопка Open emulator показаны на самом Odin.
Это обновление прежней ручной установки, не приёмка полного Setup.
[Сохранена прежняя libfm с локальным RUNPATH](odin-legacy-dependencies.json):
новый managed payload разрешает эту зависимость своим launcher environment;
Odin использует старый прямой session entry. Все зависимости ELF разрешаются.

До обновления Home с видимым Companion: 26,67% одного ядра за 15 с,
RSS 946196480 байт. После обновления диагностика подтверждает готовую видимую
сцену и отсутствие ежесекундного shell.changed от Companion (31 последовательная
секундная запись Home без этого сигнала после стартового заполнения данных). Сопоставимое ускорение
пока не заявлено: SD-карта длительно задерживает I/O (jbd2/mmcblk0p1 и ожидание
страниц), стартовый скан библиотеки не завершён и штатный guard блокирует запуск
эмулятора до его завершения. Сохранённая база **ещё до обновления** содержала
512 недоступных и 30 доступных записей; это не исчезновение игр от новой сборки.
Для подготовки копии прекращено лишнее чтение старых runtime/staging; временные
файлы обновления использовали RAM. Неудачная RAM-копия, включавшая исторические
бинарники из state, удалена; окончательная ограниченная копия перечитана успешно.
Restart из меню остановился на «Finishing your session»: два QThread ожидали
диск (`wait_on_buffer`, `blk_mq_get_tag`), заданий reboot у systemd не было.
После проверенной внешней копии инициирован обычный reboot средствами ОС.
Этот обход не засчитывается как успешный перезапуск через интерфейс.
Диагностический флаг для следующего запуска выключен. После обычного OS reboot
SSH пока не вернулся; аппаратная приёмка после перезагрузки не завершена.

### OTA: проверка выявила отсутствие рабочего канала

Владелец ограничил текущую игровую проверку фактом запуска; полноценные партии

отдельно подтверждены отсутствие игрового процесса и живой Home, это не сбой игры.

На Odin открыт Settings → System → Updates: видны `Development build` и
`Updates are not available for this build yet`. Менеджер Software отсутствует,

к OTA. Текущие адреса обоих каналов из Setup,
`https://raw.githubusercontent.com/EriArk/TrainerOS/updates/beta.json` и

отдельной немедленной проверки после запуска сейчас нет. При ручной проверке
доступная версия показывается на странице Updates, уведомление не создаётся.
Это описание реализации, не наблюдение уведомления реального релиза на Odin.

На сервере прошли 20 Qt SoftwareUpdate checks, включая фоновые уведомления,
отключение проверок, паузу/возобновление, ошибки и apply/restart guard. Python
SoftwareChannel/Installation/Release: 83 проверки прошли с umask 077. Первый
запуск с серверной umask 0002 имел 26 ошибок и одну failure: созданные тестами
файлы разрешали запись группе, строгая проверка владения/прав их отвергла.

не публичный канал и не обновление портативки.

Для реальной приёмки необходимы рабочая установка через Setup, опубликованные

apply/restart на устройстве. Нельзя подменять эти шаги тестовой отметкой готовности.


### Alpha / Beta / Stable — решение владельца и исходники

Владелец выбрал три канала: `alpha`, `beta`, `stable`. Сейчас разрабатывается
и публикуется только Alpha. Новый Setup содержит три адреса, выбирает Alpha и
предлагает только его при установке. Publisher разрешает выпуск только Alpha;
Beta/Stable зарезервированы. Settings переключает три имени, но для неактивных
каналов явно сообщает о недоступности и блокирует check/download/фоновые запросы.
Bootstrap сообщает доступные каналы приложению; состояние загрузки связано
с точным выбранным URL. Preview больше не допустим в новом подписанном feed.
Старое значение Preview в пользовательской настройке возвращает выбор к Alpha;
старые подписи, номера и кеши при этом не переименовываются.

Старый bootstrap с парой Beta/Preview отвергается **до** замены его Setup/Recovery:
его доверие и работающее восстановление сохраняются. Это не автоматическая
миграция прежнего установленного комплекта на новые каналы. Прежние архивы,
runtime и rollback не перепакованы данным изменением.

Проверки: 86 Python SoftwareChannel/Installation/Release, 22 Qt SoftwareUpdate,
5 ReleaseSourceMedia и 16 RuntimeUpstream прошли; полная x86 Release сборка
с новым QML завершилась успешно. Проверены независимые номера всех трёх
подписанных каналов, отказ от Preview, недоступность будущих каналов без запуска
worker/загрузки/уведомления, уведомление Alpha и сохранение старого bootstrap
при несовместимом контракте. Python выполнялся с umask 077; прежнее замечание
про umask 0002 не закрывается этим результатом.

Это готовность исходников и host-проверки. ARM-поставка на Odin/Flip, новый
подписанный Setup, публикация `alpha.json` и реальный OTA apply остаются открыты.
Аппаратный Flip недоступен, а Odin остаётся на прежней legacy-установке.


### Начальная проверка Alpha и подготовка реального OTA

После команды владельца установить и проверить OTA исправлены первая фоновая

временного файла с правами 0600; отдельный тест umask 0002 проходит.
Вся группа Software Python: 87 checks прошли с базовой umask 077. Это исправляет
создание ключа, а не утверждает, что все прежние тестовые каталоги при 0002 готовы.

Flip по-прежнему не отвечает SSH. Для ARM организован отдельный cross-builder
на сервере с Fedora 44 sysroot; Odin SD не используется для сборки. Установка

### Закрытый Alpha Setup и потеря связи с Odin

Собраны ARM64 и x86 Release из `14c84bc9`; большие series/cover resources
переведены на Qt BIG_RESOURCES после OOM компилятора при лимите 4 GiB.
Все 28 изменённых ресурсов совпадают с исходниками и декодируются. Проверки

`artwork_qml_smoke` завершился с 22 ошибками навигации/отображения; этот сценарий
не принят, причинная связь с изменением ресурсов не установлена.

Подготовлен **закрытый Software-only Setup**, не публичный релиз и не полный
эмуляторный комплект. Подписанные baseline 16 и target 17 содержат одинаковый

также сверён. Это серверная проверка доставки, **не применение на портативке**.

legacy-установки Odin перестал отвечать на ping/SSH напрямую и через сервер;
