# Neo Geo CD и Neo Geo Pocket: разные сетевые механизмы

2 ноября 2026, R049. Обычная Neo Geo AES/MVS уже использует прежний FBNeo
Netplay. Здесь рассматриваются оставшиеся CD и кабель Pocket; они не требуют
новых комнат, аккаунтов или отдельного сервиса связи.

## Neo Geo CD

Два игрока управляют портами одной эмулируемой консоли. Используются существующие
RetroArch rollback, выбор реле, Nearby/Online Lobby, Seats/Ready/явный Start,
Game Options/Home/Exit. `NeoCdNetplay` проверяет отдельное сетевое ядро,
целый диск и BIOS; обычное одиночное ядро и его данные сохраняются.

Выбран [libretro/NeoCD](https://github.com/libretro/neocd_libretro), исходник
`b1e04c738cb48a1dae0574b8877f6a116d270ca1`. Сравнивался также
[CD subsystem FBNeo](https://docs.libretro.com/library/fbneo/): он требует
другого пути загрузки/BIOS. NeoCD сохраняет уже используемые форматы CUE/CHD
и существующую установку владельца. Наличие save states само по себе не принято
за доказательство сетевой пригодности.

Проверка реального ARM64-ядра выявила три дефекта сериализации:

- Адреса таблиц/функций CPU попадали в снимок: разные процессы давали разные
  контрольные суммы при одинаковом состоянии. В сетевой сборке сохраняются
  нулевые указатели; штатное восстановление пересоздаёт локальные привязки.
- Восстановление HLE дополнительно записывало таблицу диска в RAM. Теперь
  возвращается точная память снимка, включая состояние до загрузки диска.
- Backup RAM не входила в снимок. Теперь она восстанавливается вместе с машиной,
  чтобы откат не оставлял записи из отброшенных кадров.

Патч [0001-canonical-netplay-state.patch](../../packaging/emulators/neocd/0001-canonical-netplay-state.patch)
меняет версию ядра на `2022-traineros-netplay1`; старые обычные состояния не
мигрируют в этот отдельный сетевой runtime. Протокол RetroArch не меняется.

Допуск — по установленному пакету и файлам, без списка названий. Поддерживаются
все CUE/CHD, принимаемые выбранным ядром; CUE проверяется вместе со всеми треками.
CCD/M3U не объявлены поддерживаемыми NeoCD только потому, что библиотека умеет
их индексировать для других движков. Учитываются каталоговые сведения об
одиночном режиме, но отсутствие таких сведений не запрещает игру.

BIOS берётся из уже проверенного `discFirmware.neogeocd`. Только этот набор
копируется в приватную папку сеанса, повторно проверяется и входит в совпадение
игроков. Дополнительный BIOS из обычной папки не может незаметно изменить выбор.
Одинаковые настройки региона/скорости задаются на сеанс; разгон и пропуск
загрузочных кадров выключены. SRAM, save states и файл backup RAM временные,
сетевая игра не пишет в одиночные сохранения. Нового BIOS или игры в пакете нет.

Вход в уже начавшуюся игру пока не включён для этого нового ядра; возвращение
в комнату не запускает игру автоматически. Два контроллера не означают native
link двух Neo Geo CD, четырёх игроков или поддержку передачи контроллера.

## NGPC / NGP

Для Pocket требуется кабель между двумя машинами. Обычный Beetle NeoPop и
его shared-console Netplay не доставляют эту возможность. Сравнены:

| Вариант | Что найдено | Решение |
| --- | --- | --- |
| [Mednafen NGP](https://mednafen.github.io/documentation/ngp.html) | Одиночная машина; общие параметры netplay не доказывают наличие кабеля | Не включать ложный профиль Link |
| [ngp-link / RACE](https://github.com/caioluders/ngp-link) | BIOS COM и UART/SIO, готовая браузерная реализация и исследование аппаратного протокола | Полезный независимый источник; не добавлять второй браузерный lobby/signaling |
| [NgpCraft](https://github.com/Tixul/Ngpcraft_emulator) | Native C++ кабельная пара, libretro TCP cable и готовый desktop mirror-протокол | Выбран для отдельного Link runtime TrainerOS |

Проверен NgpCraft `d0acb0874cc07735d7fa978539bb2471b2c1e71a`.
Его TCP cable передаёт непосредственно байты кабеля; интернет-задержка замедляет
саму игровую логику. Поэтому этот режим не выбран обычным Online-путём.
В upstream `core/netplay.py` готовый mirror-механизм моделирует обе связанные
консоли у каждого участника и передаёт нажатия с адаптивной задержкой.
Порядок машин и проверка состояния уже реализованы upstream; новой игровой
синхронизации в TrainerOS не требуется.

На ARM64 проверены четыре настоящие машины на свободном upstream link-probe,
встроенном HLE и двух mirror-сеансах. С задержкой очереди 0/6 проходов обе
стороны получили разные кнопки соперника и одинаковую память соответствующих
машин. Это локальная модель задержки, не измерение качества публичного интернета.
Штатный libretro cable test также прошёл. Ни один из этих результатов не
означал, что NGPC уже доступен в лобби TrainerOS. Следующая интеграция
и её собственные доказательства описаны ниже.

### Связка NGPC с Lobby — 2 ноября 2026

`runtime.ngpc.link.v1` использует готовый `MirrorSession` закреплённого NgpCraft.
S06 предоставляет два места, явный Start и возврат в прежнее лобби; S07 доставляет
данные через существующий `cabinet` ICE/DTLS. Нового сервера, VPN, игровой
синхронизации или автоматического старта при входе в комнату нет. Direct Nearby
и Online используют один runtime; сложные NAT сохраняют прежнее ограничение.

Допуск: локально установленный пакет с проверенными SHA, одинаковые распакованные
картриджи и настройки. Поддержаны `.ngp`, `.ngc`, ZIP и 7z с одним картриджем;
название и факт прежнего тестирования не ограничивают список. Два места Link
не исключаются из-за каталожного «1 local player». Это доступность механизма,
а не утверждение, что у любой игры есть кабельный режим или HLE совместим со всеми.

SDL frontend показывает собственную консоль, её звук и собственные кнопки;
вторая машина работает как зеркало соперника. При Home/потере фокуса ввод
нейтрализуется; общий overlay узнаёт только управляемый Python launcher.
Обычный solo-запуск через существующий NeoPop остаётся прежним.

**Прогресс Link отдельный:** `ngpc-link/<hash Trainer>/<hash cartridge>/state.json`.
Он сохраняет собственные flash-изменения, battery RAM и RTC, имеет резервную
копию перед сеансом, проверку исходной версии, атомарную замену и readback.
Запись — каждые 15 секунд и при штатном завершении. Нет импорта/перезаписи
обычных solo-сейвов; карточка режима прямо сообщает `separate linked progress`.
Это непрозрачные данные эмулятора, не разрешение семантическому адаптеру менять save.

Перед запуском участники обмениваются только ограниченными пакетами состояния:
NGF flash-различия, RTC и battery RAM. Целые исходные ROM из upstream CartExchange
не передаются; ROM остаётся локальным неизменяемым файлом. Данные другого игрока
живут только в памяти зеркальной машины. Размер, адреса, перекрытия, checksum,
очерёдность блоков и совместимость проверяются до запуска. Часы офлайн готовит
только владелец, затем обе зеркальные копии получают одинаковое значение.

При EOF/отказе/рассинхронизации обе машины останавливаются, окно остаётся с
сообщением, последняя запись сохраняется. Возврат в Lobby и новый явный Start
создают свежие transport/процессы; автоматического забрасывания в игру нет.
[Проверки, поставка и оставшиеся границы](../evidence/ngpc-link-20261102/README.md).

## Сборка, обновление и откат

NeoCD устанавливается отдельно в `TrainerOS/emulators/neocd-netplay`.
[build.sh](../../packaging/emulators/neocd/build.sh) требует точный чистый checkout,
применяет патч, собирает и проверяет перенос состояния; [bundle.py](../../packaging/emulators/neocd/bundle.py)
фиксирует SHA ядра. Пакет сохраняет upstream LGPL-3.0 и полный соответствующий
исходник со сторонними notices. У старого Z80 в этом upstream есть отдельное
условие non-commercial; корневой LGPL его не заменяет. Публичная дистрибуция
этой зависимости остаётся в прежнем лицензионном gate, не объявляется закрытой
личной установкой владельцу.
На Armada исходники, объекты и контейнеры находятся на microSD.

При обновлении проверять изменения save/restore CPU, памяти, аудио и CD,
перенести ограниченный патч, повторить межпроцессные состояния и профильные
проверки. Несовместимое изменение снимка требует новой версии ядра/настроек.
Откат возвращает прежнюю оболочку и сетевой пакет; обычный NeoCD и пользовательские
данные не заменяются.

NGPC собирается [отдельным рецептом](../../packaging/emulators/ngpc/build.sh)
из чистого закреплённого upstream; ядро и его MirrorSession не патчатся.
Пакет включает MIT notice NgpCraft, clean-room HLE, SDL frontend, SDL_ttf
и DejaVu с notices. SDL2/драйверы и Python 3 принадлежат хосту; зависимости
проверяются перед активацией. Retail BIOS/ROM и личные сейвы не входят в пакет.
Manifest связывает все исполняемые helpers и библиотеки с SHA; сетевой runtime
связывает pin, `ngpc-mirror-own-flash-v1` и upstream portable core fingerprint.
Это допускает разные архитектуры по контракту, но не доказывает проверку Deck.

При изменении подготовки состояния, HLE, таймингов или mirror-протокола менять
settings/runtime identity, повторять native mirror/сохранения/EOF и тесты Lobby.
При обычном обновлении сохранять каталог `ngpc-link`. Откат: прежняя оболочка
и удаление/замена только NGPC-пакета; свои linked saves и обычные solo-сейвы
не удалять. [Native проверка](../../packaging/emulators/ngpc/check.py) использует
свободный upstream link probe в отдельном сетевом namespace.
