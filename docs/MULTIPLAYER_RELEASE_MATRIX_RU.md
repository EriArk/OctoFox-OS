# Мультиплеер в установщике: состав, версии и оставшаяся работа

## Требование владельца — 3 ноября 2026

Первый запуск после Setup должен предоставлять готовые сетевые runtime и их
настройки. Не отправлять игрока самостоятельно искать эмулятор, ставить патчи,
указывать IP или редактировать конфиги. Допускаются поставляемые сборки,
подходящие RetroArch-ядра и автоматическое получение точной официальной сборки
с последующей локальной настройкой. Игры, собственные BIOS/console identity и
аккаунты сторонних игровых сервисов не включаются в публичный комплект.

Это требование готовности, **не утверждение, что сейчас готовы все платформы**.
Сохраняется весь согласованный охват. Отсутствие реализации отмечается как пробел,
а не как оправдание вырезать платформу. Состав multiplayer и обычного solo различен.

**Уточнение владельца, 3 ноября:** альфа может выходить с неполным функционалом.
Незавершённые режимы не блокируют её сами по себе: перечисляем ограничения,
поставляем рабочие маршруты и продолжаем разработку после выпуска. Это отменяет
прочтение прежней очереди как требования закончить все платформы до альфы.
Безопасность установки, сохранение данных и условия распространения сохраняются.

## Насколько важна версия

| Механизм | Влияние отличающихся версий | Решение TrainerOS |
| --- | --- | --- |
| Общая консоль, rollback/lockstep | Очень высокое: формат save state, порядок выполнения, RNG и настройки способны вызвать desync при внешне нормальном соединении | Одинаковые проверенные runtime/core/settings, игра и необходимые firmware. Сравнение descriptor до запуска, повторная проверка при запуске |
| Независимые машины, cable/wireless | Высокое: нужны совместимый протокол, тайминги и наш bridge; одинаковое имя эмулятора ничего не гарантирует | Закреплённый согласованный комплект, включая helper/patches; не заменять patched melonDS/PPSSPP обычным upstream |
| Native LAN/game server | Не всегда нужна побайтово одинаковая программа: участники обмениваются пакетами игры, а не полным состоянием эмулятора | Проверять edition/update, протокол/DEV9/BBA, сервис и настройки. Пока сохранять ограничения уже проверенных профилей; не разрешать произвольные версии по предположению |
| Remote Play | Эмулятор работает у хозяина; гостям его версия не нужна | Совместимы должны быть наш stream/input protocol и клиент. Это отдельный маршрут, а не универсальная замена native multiplayer |

[Официальный RetroArch FAQ](https://docs.libretro.com/guides/netplay-faq/)
требует одинаковые frontend/core/content. Более точный
[описатель протокола](https://docs.libretro.com/development/retroarch/netplay/)
описывает детерминизм и идентичность ядра; наличие save states само по себе не
доказывает пригодную скорость или совместимость любого ядра.
[Dolphin](https://dolphin-emu.org/docs/guides/netplay-guide/) требует одинаковую
версию и не соединяет несовпадающие версии. Native
[PPSSPP Ad Hoc и infrastructure](https://www.ppsspp.org/docs/multiplayer/quickstart/)
— разные механизмы, а не обычный RetroArch rollback.

В текущем ARM64 TrainerOS `RetroArchNetplay` включает хеш frontend/core в descriptor,
`PpssppNetplay` различает исправленные сборки и настройки relay, остальные native
bundles проверяют source/settings/files в своих manifest. `RuntimeMultiplayer`
сравнивает descriptor при подготовке и запуске. Нового фонового чтения всех ROM
или ослабления этих проверок данный проход не добавляет.

## Выбор runtime по существующим маршрутам

| Платформа/семейство | Сетевой runtime в комплекте | Заменять на обычное RetroArch-ядро? / граница |
| --- | --- | --- |
| NES/FDS, SNES | RetroArch + FCEUmm/Nestopia/Snes9x | Уже используется; версия frontend и ядра закреплена. FDS требует собственный BIOS |
| SG-1000/SMS/MD/Sega CD/32X | Genesis Plus GX / PicoDrive | Уже используется; disc firmware и режим контроллеров остаются существенны |
| PCE/PCE CD/SuperGrafx, Atari 2600 | PCE Fast / SuperGrafx / Stella | Уже используется; CD требует собственный firmware |
| FBNeo/Neo Geo/MAME, Neo Geo CD | FBNeo/MAME + исправленный NeoCD | Сохранить native set/parent/BIOS зависимости. Число игроков каталога не означает произвольный cabinet layout |
| GB/GBC/GBA | DoubleCherryGB/SameBoy/gpSP/mGBA Splitscreen и linked-save helpers | Уже специальные libretro routes. Обычный solo core теряет cable/RFU и защиту отдельных сейвов |
| NGP/NGPC | NgpCraft MirrorSession | Не заменить solo Beetle NeoPop: нужна связь двух машин и раздельный прогресс |
| PS1 | PCSX-ReARMed + исправленный CBIN-компонент | Уже основной сетевой маршрут. DuckStation — отдельный solo launcher; его способ получения не меняет PS1 netplay |
| N64 | RMG/Mupen64Plus + наш server/helper | Сохранить существующий native netplay; одного Mupen libretro недостаточно для равнозначной замены |
| Dreamcast/Naomi/Naomi 2/Atomiswave | Flycast Dojo; отдельно cabinet LAN и Flycast native Online | Сохранить разделение GGPO, нескольких автоматов и game-server; заменой одним core эти режимы не воспроизводятся |
| GameCube/Wii | Dolphin NetPlay; отдельно BBA и native Wii Online | Сохранить standalone bridge. Wii Remote/attachments и NAND/сервисы — отдельные условия |
| DS | Наш deterministic melonDS wireless bundle; отдельно WFC | Не заменить стандартным solo melonDS core. DS wireless и подключение к WFC — разные режимы |
| 3DS | Azahar wireless + room bridge; отдельно native Online | Сохранить patched комплект; game updates/DLC и firmware требуют совместимости |
| PSP | Исправленный PPSSPP Ad Hoc + relay/content helper | Не заменить libretro PPSSPP: потеряется существующая сетевая обвязка/исправления |
| PS2 | ARMSX2 DEV9 LAN + ps2-lan helpers | LRPS2 остаётся остановленным экспериментом, не готовой заменой. LAN-каталог не доказывает couch/Remote Play или все серверы игр |
| Xbox / Model 3 / Doom | xemu System Link / Supermodel cabinet / Odamex | Разные native протоколы; сохранить соответствующие bundles и игровые настройки |
| Wii U | Cemu native Online | Нет общего lockstep/rollback маршрута. Нужны собственные console/account данные и поддерживаемый сервис; полноценная приёмка остаётся открыта |
| Vita | Vita3K: подтверждённый отдельный vitaQuake LAN-профиль | Коммерческий AdHoc/PSN не обеспечен. Установка Vita3K или libretro-замена не закрывает этот пробел |
| Остальные системы solo-каталога | Наличие solo runtime не означает сетевой маршрут | Например Saturn/3DO/другие отсутствующие в `coreProfile` системы нельзя объявлять multiplayer-ready по числу установленных ядер. Нужен отдельный выбор механизма и проверка |

PS3/Switch не получают обещания multiplayer в этом проходе; их обычные launcher
пакеты остаются. Полный список конкретных сохранённых проверок и условий —
[в матрице](EMULATOR_MULTIPLAYER_MATRIX.md) и [готовности](FEATURE_READINESS.md).
Исторический матч на двух устройствах не объявляется новой проверкой чистого Setup.

## Установка и обновление

- Сетевой комплект, core, helper, протокол и настройки обновляются согласованным
  поколением. Не запускать встроенные updater для произвольной замены части набора.
  Чужие EmuDeck/Flatpak/профили не участвуют: используется отдельный runtime-home.
- Для внешней загрузки применяется подписанный descriptor с числовым GitHub asset ID,
  размером и SHA-256. При исчезновении asset нет fallback на `latest`: нужен новый
  проверенный descriptor. Это закрепляет идентичность, но не гарантирует хранение
  старого asset самим upstream.
- Сначала подготовить все файлы и зависимости, затем общая транзакция установки.
  Обрыв загрузки оставляет действующее поколение, а повтор продолжает частичный файл.
  Скачанные установочные скрипты не исполняются; настройку выполняет наш код локально.
- Данные пользователя не входят в публичный набор. Отсутствующий собственный BIOS
  или console identity показывается как недостающая предпосылка, не заменяется
  общей копией и не превращается в зелёную галочку.

## Сделано в этом проходе

1. DuckStation переведён в новом hybrid runtime media на прямое получение
   официального **неизменённого** AppImage. Проверен реальный asset
   `673935636`: SHA-256 совпадает с исходным установленным файлом. Он не включается
   в новое runtime media как component.tar.gz. PS1 netplay и все остальные
   бинарники сохраняются; файл устанавливается в собственный runtime-home.
2. Исправлены права запуска AppImage. Старый сборщик доверял правам скачанного
   файла/временного хранилища и мог записать `0644`; новый задаёт executable metadata,
   а deployment исправляет это и для старых кандидатов. Read-only проверка Flip
   подтвердила `0644` для DuckStation/eden/rpcs3, `0755` для остальных четырёх.
   Последующим GUI-обновлением на Flip исправление активировано: все семь AppImage
   имеют 0755 и прежние ожидаемые SHA-256, оба установочных аудита без ошибок.
3. Полный подписанный Setup 3,95 ГБ собран на сервере; 72 bootstrap файла, подписи
   и вложенные архивы независимо сверены. Закрытый ключ остался на устройстве.
   [Проверки и собранный пакет](evidence/2026-11-03-hybrid-runtime/README.md).

## Подготовка альфы и отдельная дальнейшая работа

1. **Доставлено:** hybrid Setup установлен на Flip, права и идентичность файлов
   проверены. Вход из NES Pong в выбор сетевого режима доступен; рабочие сборки
   не заменены. Это не доказательство нового сетевого матча.
2. На чистом runtime-home проверить discovery/Prepare/Ready/Start/Exit каждой
   существующей семьи через обычное Lobby. Переиспользовать прежнюю игровую приёмку
   неизменённых сборок; отдельно отметить реально новые проблемы упаковки/путей.
3. Для последующей разработки сохранить функциональные пробелы PS2 couch/Remote Play, Vita и Wii U
   по реальному поддержанному механизму. Пустая вкладка/установленный бинарник не
   заменяют эту работу. Не прятать пробелы в список «совместимых платформ»;
   завершение этих функций не является условием выпуска альфы.
4. Завершить source/license review оставшихся ядер/зависимостей и публичный
   GitHub/OTA выпуск. Hybrid delivery решает способ получения одного компонента,
   а не всю готовность/лицензии/сетевую приёмку продукта.
